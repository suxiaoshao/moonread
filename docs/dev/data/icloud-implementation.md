# iCloud 接入实施

更新：2026-10-13。开发依据为[同步设计](sync.md)，本文只记录接入步骤、实现边界与验证条件；实现进度必须以代码和实际验证为准。

## 本次范围

1. 应用固定的 iCloud Documents 目录与本地目录衔接。已有外部书架保持原授权和实际文件树，不复制为另一套藏书。
2. SwiftData 的 CloudKit 私有容器同步位置、书签、批注、章节修正、小说信息、配色方案及阅读事实；显示选择和排版留在本机。
3. 原始文件与阅读数据独立：CloudKit 不上传正文、文件夹树、文件授权、临时草稿、搜索会话、排版缓存或设备亮度等偏好。

阅读事实已接入自动同步，真实云端验收仍未完成；深入分析见[统计计划](../plans/statistics.md)。独立分享扩展、阅读记录管理中心和其他云后端不属于本文的接入范围。

## 平台接入

- 固定容器标识为 `iCloud.dev.moonread.Moonread`，根为其公开 `Documents`；工程声明 iCloud Documents、CloudKit 和必要后台通知能力。
- 首次使用云容器不可用时仍使用本机 Documents。获取容器不能阻塞 UI；正在阅读的内容不因容器检测改变视口。
- 原件通过系统协调与 ubiquity API 交接。失败保留来源；同名不静默覆盖；文件进入云目录后不维护长期双向镜像。
- 监听账户、容器与文件变化。离线不等同于换账户；退出或切换账户停止旧账户上传，不把旧账户记录或原件自动交给新账户。

构建签名、安装及跨设备验证证据统一见[验证记录](../engineering/verification.md)，平台接入不能代替实际同步交付。

## 正式用户数据实现

SwiftData 模型与 ModelActor 已接入。`Data/UserDataService.swift` 对阅读与编辑提供业务接口，`Data/CloudSync.swift` 仅管理账户/configuration 和系统同步事件；Rust 用户表、待发送记录、平台检查点和 CKSyncEngine 已删除。

源码目录整理后，同步协调与 ReaderService 扩展位于 `Data/CloudSync.swift`；原有 UI 状态与页面分别位于 `Settings/CloudStore.swift`、`Settings/CloudSettingsView.swift`。App 继续持有相同模型，协调任务与同步行为保持。

默认关闭阅读数据同步。账户可用且匹配已绑定账户时，建立 `.private("iCloud.dev.moonread.Moonread")` 容器；关闭重新建立 `.none` 的本机容器，不搬动或删除小说。账户不可用或初始化失败保留开启意愿，同账户恢复尝试，不同账户暂停并在设置显式确认当前剩余阅读数据；执行前再次核对目标账户，取消不上传且不反复弹窗。退出账户后的资料保留遵循系统规则，不保证本地及未同步数据保留。当前入口没有自选根或账户管理中心。SwiftData 自动调度同步，界面不承诺手动强制刷新。

完整 SHA 前的记录进入设备存储，正文完成后按稳定身份转入正式用户存储。批注用独立完整候选和基线保护并发，事实使用稳定 ID，封面使用外部存储。具体语义见[同步设计](sync.md)，不增加第二套通用同步引擎。

## 本地与云端验证分开

本地模型、因果冲突、删除/撤销、合并并发、事实去重/清理、附件外存与重启、后台执行、正式阅读及真实文件操作的回归结果集中记录。iOS 27 模拟器构建和启动不代表最低 iOS 18 运行或真实 iCloud 通过，证据见[验证记录](../engineering/verification.md)。

云签名条件与验收进度见 verification；同账户两设备验证范围包括：自动模式启停、旧容器在途操作、切换账户隔离、并发对象是否全部交付、离线/乱序、事实清理传播及附件上传/下载。签名及安装通过不代表跨设备云端架构已验收。

## 真实云端接入前置条件

使用有 iCloud 能力的团队为 `dev.moonread.Moonread` 签名，并在 Apple 开发者后台将 `iCloud.dev.moonread.Moonread` 关联到该 App ID。当前工程已声明 CloudKit、CloudDocuments、推送及后台通知。开发环境 schema 应与当前 SwiftData 模型一致；发布前须在 CloudKit Console 确认并部署 production schema。指定容器已获新描述文件授权；签名成功不代表云端数据交付已验收。

`Configuration.xcconfig` 默认启用云能力；当前使用开发者团队自动签名构建并安装，不覆盖为无云配置。无云 Personal Team 构建仅作为受限环境备用流程，见[开发环境](../engineering/development.md)。

文件交接的关联修复已实现，见[文件定位与 SHA 关联](README.md#文件定位与-sha-关联)：复制意图与原始字节 SHA 证据持久化，目标关联与固定根在同一索引事务发布，随后标记 published 再清理原件；暂停任务重绑并继续完成。协调与枚举移到后台 I/O 队列，已完成态快速返回，详见[执行与恢复](sync.md#云交接的执行与恢复)。合成文件回归与真实云联调分开，云签名已启用不代表真实文件交付已验收。

数据库格式变更时直接重置应用私有测试数据，不新增旧开发格式迁移，也不备份恢复应用内测试文件。外部小说原件及云目录不随开发重置修改，外部书架需重新授权添加。当前安装包与真机检查结果统一见[验证记录](../engineering/verification.md#当前安装包与真机交付)。
