# 数据、文件书架与正文身份

更新：2026-10-14。统一文件书架、本地导入和最近删除已实现；固定 iCloud Documents 与 CloudKit 代码已接入，本地回归与真实云端验收分开记录。平台条件见[接入实施](icloud-implementation.md)，签名、安装与跨设备结果只在[验证记录](../engineering/verification.md)维护。同步细节见[同步设计](sync.md)，界面见[首页与书架](../design/library.md)。

## 统一文件夹书架

所有书架都是一个真实根目录，使用同一套文件树、读取与文件管理能力。“我的书架”是内置根入口，不再维护一套独立藏书成员模型。

用户可以选择并添加其他文件夹路径，作为独立书架并存；这不是修改我的书架位置。内置根由应用管理，额外根由系统选择器授权。

| 入口 | 根目录从哪里来 | 与其他书架的差别 |
| --- | --- | --- |
| 我的书架 | 未启用 iCloud 时为应用固定本地文档目录；启用后由应用接入自身 iCloud 容器的固定公开 `Documents` 目录 | 入口及两处存储位置均由应用管理，用户不能自选根、重命名根、移动根或移除入口；是默认导入目标 |
| 用户添加的书架 | 通过系统选择器授权的本机、iCloud Drive 或其他文件提供方目录 | 可以移除入口、重新授权 |

两者内部都是真实文件与子目录，均支持改名、移动、新建文件夹和删除；能否写入由实际目录权限与文件提供方能力决定。UI 和核心规则复用，平台适配处理访问方式的差别，不以“导入书架”与“外部书架”划分两套业务。

固定限制作用于我的书架根入口及用户配置，内部文件和子目录仍可正常管理。应用负责本地与 iCloud 文档的衔接，不要求用户选择保存根，也不提供根位置设置。系统“文件”中的外部变化需重新发现，不从缓存自动恢复用户已经删除的小说。

iCloud 文件可以在系统“文件”或 Mac Finder 中整理，应用查看的是同一棵目录树。使用 iCloud Documents 的公开 `Documents` 目录并支持任意子目录层级；原文不再作为 CloudKit 附件重复保存。[Apple：公开 iCloud 文档目录](https://developer.apple.com/documentation/uikit/synchronizing-documents-in-the-icloud-environment)

## 文件与正文身份

| 层 | 职责与身份 |
| --- | --- |
| 文件 | 名称、父目录、平台定位、可用性与对应正文 SHA；目录树是事实来源，数据库清单只是索引 |
| 小说内容 | 规范化全文 SHA-256 是内容身份；正文块与章节索引按此身份组织 |
| 阅读数据 | 进度、书签、批注、事实和人工章节修正归属于正文 SHA；每条标记有独立 ID |

规范化规则及坐标见[架构](../engineering/architecture.md#内容身份与位置)。相同正文无论来自哪个文件，均使用同一内容身份及阅读记录。文件改名、移动不改变正文 SHA；正文真正修改后产生新的 SHA，旧记录独立保留，不自动套到新正文。

删除文件先把目标原件移到系统“最近删除”，文件索引随扫描移除；移到最近删除失败即按不支持处理，本批由用户明确选择永久删除或跳过，不静默降级。不增加“已解除关联文件”或待恢复藏书成员层。按 SHA 保存的阅读数据可以独立存在，不依赖保留一条已删除文件记录。必要的现存文件到 SHA 的映射用于开书定位，不成为另一套文件生命周期。

## 文件定位与 SHA 关联

正文规范化 SHA 是唯一内容身份。文件行 UUID、授权根和相对路径用于定位一份副本；大小、修改时间仅用于显示、排序和下载状态。没有平台文件 ID、版本指纹或 xattr。用户已决定本版不在原件写扩展属性，不以尚未验证的同步上传、冲突副本或未下载文件行为建立另一套身份。扫描按路径对齐，同路径同类型保留最后已知的 book_id，文件与目录互换不继承；枚举失败保留已知清单。

每次打开在后台协调访问中读取完整原始 SHA，按“原始 SHA + 解码策略（自动或手选编码）”查已准备正文。未命中时记录期望原始 SHA，导入那一遍同时哈希实际送入解码器的字节，一致才原子发布快开映射。最终正文 SHA 决定归并或新书；原书用户数据独立保留。 自动编码按 BOM、无 BOM UTF-16 零字节奇偶位置与文本校验、合法且不含 ESC 的 UTF-8、固定版本 chardetng 顺序识别，GBK 统一到 GB18030；正文仍由 encoding_rs 与 normalization-v1 生成。发布后升级识别/解码依赖须通过固定原创样本与旧 SHA 回归，不得改变已支持文件的正文结果。手选编码仅保存在本机文件行，不经 CloudKit 同步；另一台设备仍自动识别，结果不同时需手选相同编码，详见[编码与恢复](../reader/import.md#编码恢复和失败)。暂停续读先验证完整原始 SHA，再重放核对前缀；源变化保留旧任务、前缀和位置，由用户显式“重新准备”。任务 generation 继续防止旧 worker 发布。

应用内移动、改名、目录移动携带最后已知关联，立即按 file id 重绑定暂停任务定位；重启续读再从当前文件索引解析。移动不创建原始 SHA 映射。外部移动按旧路径消失、新路径新增处理，打开一次后按 SHA 接回；旧 fileRef 失效，不替换成另一副本。失效首选文件可回退到已关联副本，正式阅读新路径后更新首选。

显示边界：同路径内容被外部替换时，打开前仍可能显示旧封面、资料和进度；外部移动的新路径打开前只能按文件名搜索，作者／标签和最近阅读可能暂不包含它。阅读统计、批注与进度始终按正文 SHA 保存。

云交接依次持久化意图（路径、原始 SHA、file id、关联及解码策略）、完成复制、原子发布索引和固定根、标记 published、清理源。恢复时重新读目标字节，删源前在同次协调访问中核对源与目标 SHA；未发布不能容忍源缺失，目标被逐出或替换则保留源。保留账户隔离、完整源枚举、路径／符号链接与同名冲突保护。临时任务已归并回收时从当前行或已完成原始 SHA 映射恢复 canonical book，不依赖已删除的 pending UUID。

AI 文件提案以已下载源的原始 SHA 复核，缺少可读字节时提示准备，不主动下载。目录按授权根、路径、类型、无符号链接、子项占用与不覆盖约束检查；同路径同结构目录替换无法区分。

## 已确定的书架行为

下表是产品约定；同步代码的本地验证与云端限制见[接入实施](icloud-implementation.md)，多选交互见[书架操作](../design/library.md#操作入口)。

| 内容 | 产品约定 |
| --- | --- |
| 首页 | 最近一本为“继续阅读”行，其后最近阅读（网格为封面横排，列表为两本）与“查看全部”；下方列出固定的我的书架和用户添加的目录书架 |
| 目录与文件管理 | 共用真实文件树；改名修改实际文件名，移动改变实际位置，文件夹就是实际子目录；不另建虚拟分组或显示书名别名层 |
| 导入范围 | 单个/多个 TXT 复制进我的书架；保留来源原件。首页与外部接收默认根目录，书架内部导入使用当前子目录 |
| 导入后的导航 | 主应用单本直接阅读，继续渐进准备；多本留在目标目录逐项显示结果，失败项可重试 |
| 文件名冲突 | 在**目标目录内**按文件名检查，同名提示“替换/取消”；不同目录可有同名文件，不按正文 SHA 阻止不同文件存在 |
| 原文存储 | iCloud Documents 管理真实文件与目录，不再使用 CKAsset；未使用 iCloud 时保留本地目录能力 |
| 用户数据同步 | 阅读数据按 SHA、设置按字段通过 CloudKit 同步；开关只控制阅读数据，不用于修改内置根位置 |
| 正文准备中 | 全文 SHA 未确定前先可靠保存本机进度和标记，完成后归入正式内容再同步；阅读不等待全文完成 |
| 最近阅读 | 按正式阅读活动排序，同正文合为一项；优先上次文件，不可用时寻找其他可用副本；导入、改名、移动与临时搜索不刷新正式阅读时间 |
| 同步合并 | 下次开书优先最近正式阅读位置，远端变化不跳走当前页面；配色方案按最终状态同步，批注真正并发在同一编辑页解决 |
| 删除 | 将目标文件移到系统“最近删除”，移到最近删除失败时按本批确认永久删除或跳过；不删除其他同 SHA 文件及阅读数据，iCloud 传播由系统负责；本机下载移除是另一个明确操作 |

## 固定目录与本地可用性

固定目录衔接代码已接入；签名及真实云端数据交付的验证边界见 verification。外部 iCloud Drive 目录仍可通过“添加书架”接入。

“位置不可修改”约束用户不能自选内置根；本地目录和云目录均由应用固定管理。它不禁止应用根据 iCloud 是否启用及可用来处理实际文件保存位置。用户选择其他目录仍通过“添加书架”。

### 未启用 iCloud 时照常导入

我的书架照常接收单个/多个 TXT 和外部分享，保存到应用固定的本地文档目录；同一套目录树、文件操作和 SHA 阅读数据保持有效。无需用户额外创建目录或先开启 iCloud。

用户启用 iCloud、对应容器可用后，应用通过系统文件 API 将本地文件接入固定 iCloud 文档目录，保留子目录层级。目标重名复用替换/取消规则，失败保留可用本地文件；不维持两棵长期双向镜像，也不增加用户可选路径或整库迁移设置。

Apple 官方设计指南明确支持先保存本地、iCloud 恢复后移入的做法；这是实现本地可用性的常规文件处理，不再列为需要取舍的产品功能。[Apple：处理 iCloud 可用性变化](https://developer.apple.com/library/archive/documentation/General/Conceptual/iCloudDesignGuide/Chapters/iCloudFundametals.html)

### 与暂时断网的区别

已经使用 iCloud、只是网络暂时断开时，继续使用可访问的本地 iCloud 文件和正文缓存，联网后由系统同步，不另起一套空书架。

未登录、关闭 iCloud 或无法取得容器时，新导入仍可可靠保存本地；已有云端文件按实际可访问性显示，不能承诺未下载文件也能离线读取。退出或切换账户继续遵守账户隔离，不把旧账户文件自动上传到新账户。

原文文件与阅读数据的同步职责见[固定目录与同步控制](sync.md#固定目录与同步控制)。用户界面只有同一个我的书架入口，不需要理解底层的文件交接。

## 当前实际存储

更新：2026-10-17。用户数据已正式切换为 SwiftData；Rust SQLite 为正文、章节、来源索引和任务存储。没有旧用户表、CKSyncEngine 或双写；发布兼容以 SQLite v20 为基线。

| 数据 | 权威存储与生命周期 |
| --- | --- |
| TXT 原件及目录树 | 固定本机 Documents、自身 iCloud Documents 或用户授权的外部目录；文件操作作用于实际原件 |
| 授权与文件索引 | Rust SQLite `library_shelves` / `library_files`；设备数据，成功扫描更新，失败保护已知索引 |
| 正文、自动章节与任务 | Rust `reader.sqlite3`，schema 20：`books`、`chunks`、`reading_blanks`、`import_chapters`、`source_imports`、`import_jobs` |
| 小说信息、标签、状态、配色方案 | SwiftData `UserValue`；字段或成员最终快照，按 SHA 或配色 ID 关联 |
| 正式位置 | SwiftData `UserPosition`；取最后更新并淘汰旧更新，不保留位置历史 |
| 书签与批注 | SwiftData `AnnotationOperation`；完整内容候选和操作基线，正式保存后不维护内容历史 |
| 阅读事实与清理边界 | SwiftData `ReadingFact` / `StatisticsClear`；各设备独立事实累加，同 ID 重试不多算 |
| 用户封面 | SwiftData `UserCover.bytes` 外部存储；权威图片不是缓存，附件暂缺时文字封面 |
| SHA 完成前的阅读数据 | 设备 SwiftData `pending-users.store`，禁止云同步；完成后转入 SHA 用户存储并回收暂存 |
| 当前配色/明暗、排版/模式、设备控制、动效、记录开关 | 本机 UserDefaults；不随配色方案一起同步 |
| 任务源描述、最近隐藏、上次文件入口 | 本机 UserDefaults；任务按持有期回收；批注未提交编辑仅在内存 |
| 缩略图及图片读出副本 | 本机可重建缓存；SwiftData 附件是封面的唯一权威来源 |
| 统计汇总、章节覆盖 | Rust 从 SwiftData 事实提供的 TEMP 表计算；不写入 `reader.sqlite3` |
| AI 已提交消息、任务、队列、检查点及图片 | 本机 AIRepository；首次发送/Start 创建会话，资产随首次提交引用原子保存 |
| AI 未发送文字及附件 | 仅内存；普通对话和已开始任务均不跨启动恢复，不存在草稿数据库字段 |
| 临时查阅、搜索、会话跳转历史 | 内存；不改正式位置，原会话内跳转历史继续保留 |

SwiftData 正式用户存储为 `Application Support/Moonread/user-data.store`，按照阅读数据同步开关使用 `.none` 或固定 CloudKit 私有容器。附件由框架管理；不存在应用自建上传队列。读取入口与账户边界见[同步设计](sync.md)，封面编辑见[小说详情](../design/book-details.md#封面如何保存)。

SQLite 不是可整体删除的纯缓存。`books`、`chunks`、`reading_blanks`、自动 `import_chapters` 与 `source_imports` 是正文派生数据，在原文件和相同解码策略仍可访问时可重建；原件暂不可访问时不得自动丢弃唯一可读缓存。`library_files` 的目录元数据可重扫，但文件 ID、`book_id` 关联及用户选择的 `decoding` 不能随重建遗失。`library_shelves.bookmark`、书架名称/ID、外部根授权不可从小说正文恢复，必须迁移保留。`import_jobs` 含暂停/继续代次、来源映射和待交接状态，不能当作可随时删除的缓存；需与 SwiftData `pending-users.store` 一起保持中断恢复契约。SwiftData 中的进度、批注、书签、统计、主题、封面，以及 AI 会话/资产、UserDefaults 偏好/许可和 Keychain 凭据均非正文可重建数据。迁移入口与降级错误见[持久化演进](../engineering/architecture.md#持久化演进与发布兼容)。

Rust `books` 不再保存正式位置或最近阅读时间。`user_projection.rs` 在各计算连接中建立临时位置、元信息、事实和目录修正视图；输入来自 SwiftData，可以随时重建。`effective_chapters` 同样是临时计算视图。用户记录不依赖文件索引或正文缓存的外键级联。

首次使用本地空目录仍复制自带原创短篇；已注册内置根不会因文件被删除而再次预置。目录扫描仍只读取元数据，跳过隐藏项、包内容与符号链接；按实际目录权限工作，不主动读取整库正文。

源码入口：[SwiftData 存储](../../../ios/Moonread/Data/UserData.swift)、[用户业务接口](../../../ios/Moonread/Data/UserDataService.swift)、[Rust 计算输入](../../../crates/moonread-core/src/user_projection.rs)、[平台文件操作](../../../ios/Moonread/Library/LibraryService.swift)。

## 先统一术语

| 用语 | 含义 |
| --- | --- |
| 添加书架 | 把一个已授权真实目录加入入口列表 |
| 我的书架 | 应用提供的固定目录入口，内部操作与其他文件夹书架相同 |
| 导入小说 | 将外部 TXT 复制进我的书架当前目录，保留原件 |
| 移动 | 将选中的文件或子目录放到目标目录，成功后原位置不再保留该项 |
| 正文准备 | 解码、规范化、分块、识别目录和计算 SHA；现有 API 的 `import` 主要指这一步 |
| 导出 | 将现有 TXT 复制到用户指定位置或系统分享，不改变原文件 |
| 用户数据同步 | 独立同步 SHA 下的阅读数据与全局设置，不由 TXT 文件夹附带承担 |

## 导入与替换

1. 根据目标目录检查文件名，同名由用户选择替换或取消；不为展示冲突先哈希整本。
2. 保存文件并复用[渐进正文准备](../reader/import.md)，尽早可读；原件接收完成与可开始阅读分别记录。
3. 替换先接收新文件，成功后提交；失败或取消不损坏旧文件。
4. 正文 SHA 相同继续使用原阅读数据；不同则归入新的内容身份。
5. 导出当前真实文件，保留原字节和编码，不从规范正文缓存重建原件。

文件移动或改名后的新名称直接参与后续目标目录的冲突检查，不保留另一份“最初导入文件名”作为独立身份。同一批文件逐项处理，单项失败不撤销已经成功的文件。

## 移动与复制

内置目录和用户添加的目录共用文件操作，不再限定文件夹间整理必须去系统“文件”。

| 操作 | 行为 |
| --- | --- |
| 新建文件夹 | 在当前可写目录创建真实子目录 |
| 重命名 | 修改真实文件或子目录名称，更新定位，SHA 与阅读记录不变 |
| 移动 | 选择可访问且可写的目标目录，支持书架内及书架之间移动；目录层次随实际文件系统改变 |
| 导入到我的书架 | 复制选定 TXT，原文件保留 |
| 导出/分享 | 单本或多选复制现有 TXT 到目标位置或系统分享 |
| 删除文件或子目录 | 选中项移到系统“最近删除”，移到最近删除失败时本批确认永久删除或跳过；根书架入口的移除另行处理 |

同一文件系统尽量使用原生移动；跨文件提供方如果需要复制后删除，必须先确认目标完整保存，再删除源项。失败如实反馈，不把“只复制成功”展示成移动完成。重名复用替换/取消规则，不静默覆盖。

此处文件修改明确涵盖名称、位置和目录结构；阅读过程不修改正文。正文编辑器尚无交互设计，不因文件管理顺带增加。

## 恢复文件夹引用

用户添加的书架失效时保留入口，提供重试或重新连接；主动移除后用原有添加入口重新选目录。移除仅清目录配置与授权，不递归删除目录内容，也不保留来源回收站。我的书架不提供移除入口。

已知文件清单先显示，后台更新；扫描不读取全部正文。系统“文件”中的改名、移动、删除和新建需要刷新到当前树；授权或提供方暂时不可用不能当作真实删除。开书后按正文 SHA 关联原记录，不为刷新目录先哈希整库。

## TXT 分享与默认打开

系统分享、外部打开和应用内选择共用 TXT 导入流程。首页及外部接收默认导入我的书架根目录；复制接收保留来源原件，与用户明确点“移动”区别清楚。

当前已声明 TXT 文档打开类型，`onOpenURL` 进入复制接收流程；应用内系统选择器支持多选，导出与分享使用系统组件。独立 Share Extension 尚未实现，不能据文档类型声明承诺所有宿主的分享面板都提供月读入口。

声明系统已有的 TXT 类型，由用户在系统选择月读作为打开应用；分享扩展按实际宿主需要接入。临时文件在有效期内持久接收，不依赖宿主保持运行。平台依据见[分享接入](sync.md#验证边界)。[Apple：默认打开 App](https://support.apple.com/zh-cn/guide/iphone/iphe4bff8827/ios)

## 保存、清理与删除边界

- 文件删除作用于目标原件，先移到系统“最近删除”，可在“文件”App 恢复；移到最近删除失败时本批确认永久删除或跳过。iCloud 的传播由系统负责。文件索引随扫描移除，阅读记录仍按正文 SHA 保存；恢复后重新扫描为新文件行，打开时按 SHA 接回原记录。
- 用户添加的根书架可以移除配置；我的书架入口固定。应用内不能删除内置根，不限制用户在系统文件工具中的权限。
- 规范正文、索引与排版缓存留在应用私有目录；SQLite 不放进小说文件夹同步，不把笔记写进每个 TXT 的伴随文件。
- 移除本机下载使用平台相应能力，保护未上传的唯一原件；应用同时处理不再需要的派生正文，避免名义清理而实际保留全部占用。
- 源文件暂不可用时保护唯一可读缓存；不要把缓存当作待恢复文件库，自动复活用户已删除的原件。
- 替换或移动中断不得损坏原件；现存文件索引可以重新发现，原始文件与 SHA 阅读数据各自可靠保存。

Rust 管理正文身份、计算与索引；SwiftData 管理用户数据，Swift 管理授权、文件协调、iCloud 文档状态与通知。物理数据格式按发布兼容与迁移契约演进，不静默清空旧数据。

## 当前范围与验证

独立阅读记录页面、统计与其他候选的状态统一维护在[后续计划](../roadmap.md)。

本地内置/外部根、搜索范围、嵌套返回、实际文件操作、重名保护及记录保留的结果集中记录；目录变动由文件呈现通知、前台刷新和手动刷新驱动。跨文件提供方移动、云端下载、授权失效恢复与真实文件分享宿主仍需对应环境验证，见[验证记录](../engineering/verification.md)。

业务层每次读取组合 SwiftData 与正文计算输入，创建独立的只读 `ReaderQuery`。输入仅属于该查询的 TEMP 连接，不刷新共享可变表；界面只使用业务服务返回的最终有效数据。目录、章导航、正文快照、搜索归属、信息与统计都按此边界查询，长任务固定启动时的计算快照。
