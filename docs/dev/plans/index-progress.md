# 索引进度说明（#140，设计待审）

来源：2026-10-27 的进度指示调查及用户对索引页留白的反馈，2026-10-30 整理。关联 [#140](https://github.com/suxiaoshao/moonread/issues/140)。本页记录待设计范围，不表示已实现或授权实现；版本取舍以路线图为准。

## 问题与范围

当时索引页显示「已索引 n / m 本」和系统直线进度条，但进行中不显示当前文件。单本耗时较长时，条停在同一位置容易被理解为卡住。页面也没有说明「完成」关闭页面与「停止」取消任务的区别。

只整理索引页呈现，沿用现有索引调度、后台任务与取消规则。阅读位置、小组件进度、正文准备、搜索、识别目录和数据管理遮罩不纳入本项；它们不是同一种任务，不为统一外观替换共用控件。

## 待审方案

保留按本计数的系统直线进度条，显示当前文件，不估算剩余时间。状态组按用户反馈居中组织：图标、正在建立索引、已完成/总本数、进度条、当前文件名与离开说明；具体图标与留白先通过效果图确认。未开始时同一区域显示存量与开始操作，不用活动进度条暗示正在运行。失败列表与 iCloud 选项仍可访问。

说明应忠实对应当时已有行为：点「完成」只关闭页面、前台任务继续；切走 App 且无系统持续处理任务时会暂停；低电量或过热会暂停；「停止」才取消。实施前按当前 `FullIndex` 控制器重新核对这些规则，不能靠改文案承诺系统会一直后台运行。最低系统下的任务降级见[系统集成](../design/ios-integration.md#书架索引后台任务)。

## 下一步与验证边界

先给用户看进行中/未开始两张效果图，再决定实现。通过后仅在既有 controller 向页面提供当前对象与状态，文案进入原本地化表，不新增调度器。验证当前文件是否可读、关闭与停止是否符合说明、长文件没有假剩余时间；不为这项呈现整理重新运行整套阅读 UI 流程。
