# 对话错误与单次操作确认

更新：2026-10-04。以下交互已接入正式 Agent 页面；真实账户与最低系统验收见验证记录。

## 当前实现

Agent 已有停止、部分输出与工具结果保存、工具结构化失败、调用确认及中断恢复。网络与 API 错误按已知安全类别显示短句，覆盖网络中断、超时、认证、限流或额度、服务不可用和请求未接受；其他情况使用通用失败，不展示原始服务响应。SDK 常规请求不自动重试；输入超窗的一次压缩重试有独立限制，见 [Agent](agent.md)。

确认机制已绑定具体调用及对象，拒绝返回 denied，相同调用不会在本次运行中重复请求确认；停止会取消等待。现有用途是下载/解析正文前的单次确认。正式页面已接入单次准备确认卡；这不是通用权限管理系统。

## 每轮回复的展示

- 运行时直接展示中间回复；两段普通回复（或补充消息）之间连续的推理和工具调用归为一组，默认收起。组标题显示当前活动，完成后显示动作摘要与调用数量；单个活动直接用一行呈现。
- 推理标题直接预览服务返回的文本，单行尾部省略，展开看完整内容；使用 `sparkles`。真实 reasoning-start 事件尚无文本时显示“思考中”，没有推理事件的请求等待显示“等待回复”，不补造推理。
- 分组、推理条目和工具条目分别按真实运行状态显示系统小型 ProgressView；完成、失败、停止、等待确认均停止对应加载动效。减少动态效果使用静态沙漏。
- 工具行轻量呈现图标、动作和状态，点击打开详情 sheet 查看参数与结果；来源预览入口放在相应结果内，不在最终回复下重复列工具来源。
- 过程文字统一一个层级：`.subheadline`、主题次要文字色；正在进行的分组或条目标题改用正文色（分组标题加中等字重），失败用危险色；“查看过程”与之同级。紧凑行高 32pt、条目间距 4pt，整轮过程、活动分组与推理全文统一使用原生 DisclosureGroup，箭头与内容展开由系统处理；完成工具不逐行重复“已完成”；加载、异常和部分结果保留状态。组标题使用简短类别，避免串联全部工具名称。
- 当前页完成时过程保持展开；重新打开时已完成轮次折叠为“查看过程”，用户可展开，最终文本块身份保持。见[消息呈现](rendering.md)。
- 失败、停止、等待确认时默认保留过程。已经收到的部分回答和已完成工具结果保留；错误行位于该轮末尾、过程折叠之外。
- 工具失败显示在相应调用上，模型可以继续处理；不能将一次工具失败直接等同整轮失败。模型请求失败才显示本轮请求错误。
- 错误不遮挡输入框，也不阻断返回阅读。状态必须来自真实事件。

## 请求失败后继续

请求失败后，在本轮末尾显示简短、安全的原因，例如网络中断、请求超时、认证失效或额度不足；不能可靠识别时显示“请求未完成”。保留已经显示的内容与工具过程，输入框照常可用。

不放重试、重新登录、切换模型、错误详情等配套按钮，不做倒计时或专门恢复流程。用户自行处理网络或连接问题，需要时通过已有入口换模型，再发送“继续”或其他消息。

“继续”是普通 user 消息，沿用同一对话的正常发送与 Agent 循环；不解析为特殊恢复命令，不自动重放上一轮，不保证从失败的 token 或工具步骤断点续传。已有消息和工具结果按正常协议投影，模型自行决定后续动作。普通网络/API 失败不新增自动重试。已有输入超窗压缩策略独立处理，不扩展为通用故障恢复。

错误原因来自可靠的网络错误类型或供应商结构化错误，不展示原始响应、凭证、请求体或小说原文。不能把所有 429 都认定为额度不足，也不能把所有失败都要求重新登录。停止、拒绝及工具失败继续保持各自语义。

### Pi 对照

本地 Pi `1b347794e` 的 `packages/coding-agent/src/modes/interactive/components/assistant-message.ts` 在消息内容后显示错误文字，没有逐类恢复按钮。其 `core/agent-session.ts` 与 `core/settings-manager.ts` 另有可配置的自动重试机制，因此不将 Pi 描述为完全没有重试。月读采用简洁的消息呈现与正常输入继续，不引入这套自动重试机制。

## 正文准备确认

卡片显示具体书籍、待执行动作（下载、解析或两者）及已知大小；未知大小不编造。卡片为 `surface` 底、1pt `border`、16 圆角，原因用次要文字；主按钮“准备正文”使用主题实心按钮（accent/onAccent），次按钮“暂不准备”为普通描边按钮，空间不足时纵向排列。执行前重新校验对象及文件授权。

用户确认只适用于当前操作，不授予长期权限。拒绝后该工具显示“未准备”，模型可使用已有信息继续回答，并说明受限范围。关闭对话弹窗不等于拒绝；停止取消等待；应用重启不自动批准或重发。

不增加“始终允许”、权限管理页或通用授权中心。文件夹的系统访问授权继续由现有文件服务处理，与这次准备确认分开。后续资料/书架方案的确认应用遵守各自业务契约，不扩展为模型可直接写入的权限。

## 对话容器

标题栏与消息区使用所在作用域的不透明底色：对话 Tab 为 App `canvas`，阅读弹窗沿用阅读作用域，与其他阅读弹层同为 `surface`；不另设 AI 配色。

- 用户消息靠右、按内容收缩宽度，`accentSurface` 底、正文色、16 圆角；常规字号左侧至少留 48pt，辅助功能字号缩到 16pt，长中文与大字号仍可舒适换行。消息附带的阅读附件以次要色小字列在气泡内。
- 回复不加底框，直接显示 Markdown；复制按钮与“已停止/回复已中断”位于回复下方同一行。轮间距 24pt，轮内 12pt，左右页边 16pt。
- 输入框为 `surface` 底（阅读弹窗用 `raised`），1pt `border`，聚焦时改为 `focus` 色，20 圆角。发送与停止为 accent 实心圆配 onAccent 图标，不可发送时为 `selected` 底与次要色图标；`+` 与发送方式菜单的触区不小于 44×44pt。供应商图标保持原色。
- 待发送附件为 `input` 底、8 圆角的小签，按宽度换行排列，长摘要中间省略，`×` 只移除该项；小签与 `×` 的点按区域均不小于 44×44pt，只在其中绘制较矮的底色，相邻触区不重叠；排队消息位置不变，使用 `input` 底与描边。
- 请求失败由运行器状态和历史映射，显示在对应轮次末尾；保存、提交、删除等临时操作失败用原生可关闭弹窗通知，不保存为对话错误、不常驻输入框上方。
- 工具详情不显示 UTF-8 起止位置、上下文偏移、读取上限及内部引用等坐标字段；“查看原文”等来源跳转保留。

消息区域使用原生交互式键盘收起，空对话也允许下拉；点击消息区域可解除输入焦点，不清空草稿，点击手势与子项操作同时识别。离开底部时显示居中的圆形向下按钮，点击回到底部；滚动几何判断位置，用户查看上方消息时不被流式输出强制拉回。
