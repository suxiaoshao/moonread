## 代码职责

- Providers：认证、选定连接的请求适配、工具 schema 协议转换、模型能力/容量、usage 与结束原因归一化。新增模型不能靠隐式 Codex 默认。
- Agent：会话运行、工具注册与执行上下文、追加队列、预算/压缩、确认协调和消息投影。继续复用 SDK streamText 工具循环。
- Tools：调用 ReaderService 等最终业务服务，返回稳定业务结果；无 UI、无直接数据库/任意文件访问。
- Data：消息/工具调用/结果、摘要检查点、已提交排队输入、确认提案与附件引用；按页查询，未发送草稿只留内存。
- UI：只观察应用状态、显示工具活动/引用/确认并提交用户操作，页面关闭不销毁任务。

不用独立 package、通用插件系统或持久后台任务引擎。读写数据格式按当前开发阶段直接调整，不增加旧开发版迁移分支。

## SDK 与界面库接入边界

- 十个业务工具使用 `TypedTool<Input, Output>`；异构注册表擦除类型仅用于 SDK ToolSet 和持久协议消息。SDK 生成基本字段并负责 schema 校验及 Codable 转换；可选枚举/数组推断缺口、引用长度与业务范围在同一输入定义补充。`strict:false` 保留真正的可选字段，接受省略或 null，不让模型用空串填齐无关引用。跨字段关系仍由业务代码负责。
- `Schema.codable` 本身只解码，不执行 JSON Schema 数值/长度规则。擦除后的 ToolSet 显式使用 SDK JSON Schema validator；typed execute 使用同一份 schema 解码，避免误以为 Codable 等于完整约束校验。
- 多步循环继续交给 `streamText/prepareStep/stopWhen`；执行返回值使用 SDK `ToolExecutionResult.resolve()`，应用不重复实现 value/future 分支。
- 用户确认保留当前应用级等待/拒绝/关闭恢复语义。SDK `needsApproval` 是另一种 approval 消息及续传流程，不与现有确认路径叠加。正文准备租约、队列、持久化和压缩预算属于应用职责。
- 自定义 URLSession fetch 仍通过 SDK FetchFunction 注入，只负责及时交付网络字节与取消，协议/SSE 解析由 SDK 承担。动态输出限制适配保留，因为 prepareStep 不能更新 CallSettings。
- 回复文本使用原生 MarkdownView，消息列表为 UITableView，按块稳定身份与会话缓存增量呈现，UI 显示缓冲独立于 runtime 权威文本。视图消失不取消网络任务或正式历史；细节见[消息呈现](rendering.md)。

## 供应商无关的能力选择

模型请求身份为 connectionID + modelID，每次模型步骤取得配置快照并校验能力。空配置明确要求选择连接；移除/失效不转向其他账户；自定义服务不默认 Codex。只读工具集对当前书/其他书使用相同 schema，稳定工具顺序利于前缀缓存。

无工具能力模型可进行纯文本聊天，但不会虚构已读正文；依赖工具的快捷任务不能启动，提示选择支持工具的模型。不以“模型会写 JSON”伪装支持工具。四协议都需覆盖调用、结果、usage、取消、结束原因和错误投影；认证方式与协议是不同维度。

保留供应商要求的签名/不透明内容、callID、工具名、输入和结果。跨供应商切换时只携带可转换的完整轮次：可移植的工具调用/结果映射为目标协议；无法安全映射的历史转为带来源的文本资料，不携带旧签名。不得凭全局同名模型复制其他账户权限。

## 一个用户轮次的执行

1. 保存用户输入及所选配置；检查凭证、能力与上下文预算。
2. 以 ToolSet + prepareStep + 显式 stopWhen 调用 SDK。partial arguments 只用于展示，不执行；完整且校验通过后执行。
3. 记录每个模型步骤的有序 parts、调用 ID/参数；工具结果按 callID 对应，不能按异步完成顺序错配。callID 只用于协议配对和当前步骤的结果保存，不用它缓存命中或拒绝后续调用；新步骤收到调用时正常执行。
4. 同一步独立读取由 SDK 并行执行；每次搜索调用独立取消。等待用户确认暂停新的自动步骤；已经完成的读取结果保留。后续写入只由应用确认执行器串行处理。
5. 正常工具失败成为结构化结果供模型处理，不写成“没找到”；参数错误允许模型修正。取消是运行终止，不诱导模型继续重试。
6. 当前批调用均有结果/终态后，SDK继续下一模型步骤；边界接纳 steering，重新做预算。没有后续工具调用时结束当前工作，再处理 follow-up。

执行循环遵循 Pi：不设置固定模型步骤数、工具次数、重复调用计数、工具结果缓存或通用工具执行超时。工具返回后继续交给模型决定下一步；模型不再调用工具、用户停止或请求失败时结束。callID 仅用于协议配对。

结束区分 completed、stopped、failed、interrupted、limitReached、needsConfirmation；finish_reason=length 是截断，显示原因，不自动无限续写。网络失败不自动重放可能有副作用的后续工具。

### 确认、准备与恢复

使用应用级确认等待，最终映射为普通配对工具结果，避免将私有 approval 消息发送到不支持它的协议。需要准备的只读工具在批准执行前先检查状态；批准绑定具体对象与请求。确认后再次校验身份，再执行原工具。正文变更、授权丢失返回相应错误。

关闭弹窗：运行/确认状态保留，月亮显示等待标记。拒绝：返回本次 denied 结果，模型可基于已有结果解释；后续请求同一操作时重新询问，不缓存拒绝决定。停止：取消网络、待执行工具、确认等待与本任务资源；已完成操作不撤销。重启：运行标为中断，未确认请求失效；重新继续时再次展示最新方案，不能自动准备、付费请求或写入。

四协议共用应用确认路径；SDK 原生 approval 路径不启用。单次操作是否获准以应用记录为依据，模型文本不能批准。这不构成长期权限系统。错误分类、实际实现边界与界面行为见[对话错误与单次操作确认](errors-and-confirmation.md)。

## Steering、follow-up 与切换模型

队列项：id、conversationID、text、createdAt、mode=steering|followUp、state=queued|consumed|cancelled。用户点发送立即保存并可见；消费时原项进入对应历史位置，不能再追加一条重复 user message。

- steering 默认，在下一处理边界加入，不强行切断当前模型请求、不撤销已完成读取。一个边界按提交顺序接纳当时已排队的 steering；执行中的调用先正确收尾。
- follow-up 在当前工作结束且 steering 用尽后按提交顺序处理，作为新用户轮次清除当前步骤结果及上下文超限重试标记；前一轮拒绝不代替新一轮确认。当前模型直接返回最终回答但有 steering 时，继续一个新的 SDK 调用消费它；外层只调度用户消息，不重写 SDK 内部工具循环。
- 选择新模型不改变已经发出的请求。下一次模型请求（包含工具结果后的请求）使用最新明确选择，重算预算/工具能力/历史转换；切换到无工具能力时不能丢弃未配对调用，先收尾，再以纯文本继续并显式提示限制。
- 停止保留排队消息为待发送，不自动在停止后启动；用户继续才消费。进程重启也不自动发送队列。不引入消息分支或恢复中心。

不同会话有各自任务、transport、队列和工具取消令牌；一处停止或换模型不修改其他会话。

## 消息、持久化与分页

首次连接读取最新一页，结果卡片直接由其中的成功工具消息解码；不另行恢复全历史结果或计数。用户加载更早消息时向前插入并按稳定 ID 去重，已加载范围不会被运行更新缩回。数据库提交返回此次新增/变更的记录，运行器发布成功提交的记录与对应 head；服务按 ID 追加或替换对应记录。结束、失败、停止只更新对应历史记录的 outcome/error。流式文字、推理及工具活动仅更新当前运行投影，不读取数据库历史。分页返回不覆盖期间已收到的更新。

不能继续将整个多步轮次折叠成一条 assistant.text。按顺序保存 assistant步骤、toolCall、toolResult、来源、usage、结束原因和协议元数据。工具状态有 queued/running/waitingConfirmation/completed/failed/cancelled；结果可以先于其他调用结束，但显示和回放按步骤及callID关联。

一个callID只能写入一个最终结果；增量/preliminary结果只更新展示，不作为多个正式结果重放。终止前没有结果的调用保存取消/中断终态；下次请求修复配对或转换为文本记录，不孤立发送 toolCall。

Agent 存储提供每页最多50条的前后 keyset 查询，按会话、递增 sequence 和稳定消息身份保存。运行输入按预算加载。页面首次读取最近50条，按需向前加载50条，使用惰性列表渲染。从搜索结果打开时读取以命中消息结尾的一页及其后一页，形成历史窗口：上方继续向前加载，下方“加载较新消息”向后读取50条；窗口未到最新时运行器提交的新条目只更新已在窗口内的记录、不插入，流式输出也不显示在窗口末尾，“回到底部”或发送新消息时换回最新一页。会话列表本身尚未分页，主动加载的旧历史不自动回收，长会话内存仍需实测。

每条历史记录保存一份 `searchText`：user 消息只取 `userText`；assistant 消息没有任何 `tool-call` 部分时取文字部分与 `content.value`，不检查 finality、outcome 或 finishReason，带有工具调用时整条消息的搜索文字为空。reasoning 部分和 tool/system 消息不参与。已保存的无工具调用中断正文、被后续 steering 回答移入过程的较早正文仍可搜索；尚未消费的队列和未提交的流式投影没有搜索记录，附件上下文展开也不进入 `userText`。对话搜索用 SwiftData `localizedStandardContains` 查询该列，只保留已列出会话中每个会话最新的命中记录；标题匹配独立处理。当前按命中 sequence 加载窗口、按整轮居中与高亮，不自动展开隐藏的命中，详见[当前语料与定位](../design/ai.md#对话搜索的当前语料与定位)。这些行为本次只记录，语料与定位调整留待后续讨论。附件独立存储、正文/工具输出按工具上限保存。UI渲染快照与SDK临时投影不成为第二份可编辑历史。发送窗口、完整历史、摘要检查点用途不同，数据库分页不能删历史。

## 上下文预算与压缩

每个模型步骤计算指令、消息附件、工具schema、当前摘要、近期消息、图片和预留工具结果的总预算。模型容量来自已解析的当前连接目录；缺容量的手工模型须补充，不能默认大窗口。SDK没有统一容量字段，usage字段必须在Providers归一化，缓存读取不能和已包含缓存的输入重复相加。

上下文预留16384 tokens，近期完整消息/配对工具组保留目标20000 tokens，采用 Pi 的默认值。正式输出取已知目录上限与实际剩余窗口（4096余量）的较小值；缺输出规格时仅按已知上下文容量约束，不再假定4096输出。摘要输出最多13107 tokens，受模型及实际剩余容量约束，沿用用户当前思考档位。超大历史条目按文本片段摘要，不丢弃原始历史。SDK Anthropic 手动思考预算由适配层抵扣，保证最终 wire max_tokens 不超限。

上下文遵循 Pi：取最近一次有效 assistant 步骤的服务端 inputTokens + outputTokens，只估算其后新增消息和工具结果；无有效用量时按 UTF-16 字符数/4估算。不再按配置指纹使实际用量失效，不额外增加缓存输入。真实 usage 保存输入、输出、缓存读写和推理 token（未返回时保留 nil）。估算是发送预算的回退值，不是精确 tokenizer。

压缩按消息/配对工具组切分，允许压缩同一长轮次内较早的步骤，不能在assistant调用与tool结果之间截断，只对模型输入投影生效。摘要检查点只保存 summary 和 throughSequence；预算由当前运行配置计算；成功且未截断后原子替换检查点。保留目标、用户要求、事实与推断区别、正文身份和来源、已应用操作、待办；原文摘录不能变成新权限。

总结请求无修改工具，默认当前模型；旧历史过大时按有限历史范围分块总结后合并，每块均受模型输入预算约束，不用固定摘要次数把正常长历史误判为容量不足；每块推进历史游标，不递归重试。摘要失败/取消保留旧检查点和全部历史；压缩期间排队输入在结束边界接纳。输入超窗最多一次压缩重试，仅针对被拒绝且未执行工具的请求；输出截断不触发自动续写。SDK/Providers须将该错误与普通网络失败区分。

## UI 接入与验收边界

工具类别、动作名称、图标及状态分离规则见[工具调用展示](tool-presentation.md)。过程、工具详情、准备确认、月亮活动和来源预览已接入。

界面显示真实正在执行的搜索、读取、统计、压缩、等待确认；月亮来自同一状态投影。并行工具按数量/主要活动展示，不显示未经事件支持的“模型正在思考”。引用可跳回，工具详细结果按需展开；普通文字回复不强制卡片化。

## 当前实现与验证边界

运行器复用 SDK 多步循环。步骤持久化从下一步 `prepareStep` 的完整 `steps` 提交，最后一步从 `result.steps` 提交；不依赖 `onStepFinish` 与下一步准备的通知先后，避免工具结果漏入下一次请求。未完成调用和已完成结果同步保存在会话头，进程中断后补齐取消结果且不自动发请求。

定向测试覆盖运行器与全部工具，包含四协议的合成 SSE 工具往返、队列、模型切换、确认、停止、中断恢复、压缩及实际 Rust 正文查询。详见[验证记录](../engineering/verification.md)。这些不是真实账号和云下载验收。

应用入口已切换到 coordinator；生成中过程展开、当前页完成保持展开、重开时折叠，最终回复独立展示；工具详情用单层 sheet，校验后的来源打开只读原文预览，不写阅读位置或统计。联网和图片按已配置的原生工具服务接入；资料写入和书架整理已接入同一业务提案流程，不注册空实现或伪造服务能力。

### 新输入设计的接入要求

页面信息改为 user 消息内的 readingAttachments，详见[对话骨架与阅读附件](../design/ai.md)。coordinator 已移除固定入口提示；队列输入支持 readingAttachments，并在 user 消息投影中发送。正式页面直接使用该队列与历史投影。正文 SHA 的会话关联仅用于导航，不再成为隐含系统上下文。旧文本服务已删除。

### 会话、草稿与展示分类

所有未发送输入和阅读附件只在应用内存保留，不存入数据库、不跨启动恢复。普通聊天首次发送前不创建会话记录；首次发送在同一 AIRepository 事务创建会话、模型选择、附件资产和首条队列输入，并列入列表。保存失败保留内存输入供重试。发送提交 Task 存在时禁用整个输入区，并由服务拒绝文字、附件和模型修改；提交完成后恢复，不等待模型生成结束。快捷入口 Start 创建的未列出任务、已提交队列、运行检查点及历史跨启动保留；开始前纯表单不创建会话。快捷入口“转入对话”只保存 listed=true/origin=nil，不复制历史或资产、不换运行器。初始目的在首条可见用户输入中，系统指令保持统一。存储／资产 first-reference／工作投影及删除事务见 [内容技术设计](../engineering/ai-architecture.md#统一持久会话)。
