# AI 消息呈现与滚动

当前使用 UITableView 块列表、文本块原生 MarkdownView、会话级展示缓存与流式显示缓冲。UI 投影不改变 runtime 权威内容、请求或持久化节奏。源码职责见[AI 架构](architecture.md)，候选优化见[性能设计](../engineering/performance.md#待优化)，实测和用户反馈只在[验证记录](../engineering/verification.md)。

## 稳定身份与增量投影

同一 text/reasoning 块从 live、工具开始、step 提交、完成到重开，ID 和父级归属保持一致。ID 采用 turn/s{step}/p{part}，part 只计 text/reasoning；工具沿用 toolCallId。assistant entry 持久保存 turn 内 step 序号，head 保存当前 step，不能从当前 50 条窗口推算序号。runtime 按真实出现顺序保留 pendingParts 与工具位置，provider span ID 只用于匹配增量，不作展示身份。中断按有序 parts 重建，持久化格式演进须保留旧历史可读并验证迁移。

单个 turn 输出按流式顺序的块列表，最终回答是最后一个 text；不在 answer/process/committed 容器之间迁移文本。已提交投影仅在 entries 改变时重算，流式 tick 只更新活动 turn；结构变化走完整投影。UI 的行值 Equatable，observer 仅在 head/running/confirmations 真正变化时发布；稳定 group 以首个 item ID 归属。

用户选择完成时保持过程展开；重新打开会话时，已完成 turn 折为“查看过程”。折叠仅插入/移除过程行，不改变最终文本块身份。复制、已停止/中断等操作栏仅在 turn 结束后出现。

## 回复反馈

长按已结束的回复文本或其操作栏，可选“反馈这条回复”。邮件收件人取 `AppLinks.supportEmail`，预填当前 App 版本、该文本块对应持久化请求的服务商／模型及所选回复，不包含其他会话、用户问题、隐藏思考、附件或凭据。连接存在时显示连接与模型的可读名称；连接已移除时服务商显示“已删除的连接”，模型保留该条请求的模型标识，不显示内部连接 ID，不改变持久化格式。

原生邮件撰写器可用时打开系统撰写页；否则用已编码收件人、主题和正文的 `mailto:` URL 打开默认邮件 App，打开失败后才显示可滚动、可选字的备用页，收件人／主题／正文均可独立复制，也可复制全部。用户自行编辑、取消或发送，应用不自动发送邮件。隐私政策与帮助页同时说明反馈包含所选回复内容。

## 表格与 Markdown

行模型包含任务头、较早/较新入口、用户消息/队列、文本、过程/工具组、等待、确认/结果卡、图片、错误和结束操作栏。结构变化 diffable apply，内容变化只 reconfigure 对应 ID；快照不加默认动画。其余 SwiftUI 行使用 UIHostingConfiguration，主题/AIService 环境一致，水平边距使用 LayoutTokens.content。

AI 回复及过程文本用 UIKit MarkdownView；流式时使用库的未闭合标记处理，turn 结束按完整原文重解析。按块 ID、内容 hash、流式状态和主题缓存解析结果；按块保留显示 view，cell 挂载已有 view，不能只设初始文本后重建空 controller。sizing view 池上限 24；显式测量高度并缓存，文本行不依赖 SwiftUI 自适应。非文本行仍使用自适应 hosting，高度变化遵循 selfSizingInvalidation。

高度键含块 ID、内容版本、宽度、Dynamic Type；宽度/字号改变失效，未命中按类型/文本长度估算。缓存随会话释放、不持久化；parsed/retained view 的长期容量限制尚待测量，不把 sizing pool 上限当全缓存上限。

整条回答可复制，局部选择沿用库和系统，不另造跨 Markdown 块选字流程。字体、颜色、行距随主题及 Dynamic Type；一至三级标题采用既定字号比例，有序列表为普通数字加句点，去掉强调下划线。代码/表格/段落间距使用库样式，代码行号为接受的差异，不 fork、不访问私有类型。文本选择、复制和链接保持可用；原生容器的辅助功能 label 来自解析节点，链接提供 custom actions，实际 VoiceOver 顺序/自动滚动的验证状态见 verification。

## 跟随、锚点与输入区

用户开始拖动立即停止 following；拖动/减速结束接近底部（约 24pt）恢复，发送或点回到底部恢复；程序滚动不改变 following。搜索居中并高亮目标后停止 following。非跟随更新前记录第一个完全可见行 ID 与屏内偏移，更新布局后恢复，同样覆盖头部分页。

输入区占底部 contentInset，排队胶囊额外占其实测高度与间距；胶囊和回到底部按钮为 overlay，不改变表格视口。inset、键盘、输入框高度变化在同次布局中处理，非跟随恢复锚点。交互式收键盘及点空白收键盘保留。排队气泡复用用户消息、0.6 不透明度，菜单和无障碍动作可取消；多条胶囊可逐项取消。无数据变化不让全历史重建。

## 流式显示缓冲

UI 按活动文本块 ID 记录已显示长度，与权威文本分离。CADisplayLink 仅积压时运行，以约 200ms 目标时间追赶、批次 250ms 追赶保护，至少一个完整字素；不切 emoji/组合字符。中文按字素、英文按空白跨词提交，同帧最多一次 reconfigure，预算不足可在测量后调到隔帧。

后面出现新块/工具/reasoning/确认、turn 结束/停止/中断、离页或后台时立即放完，保持顺序；历史和重开直接完整显示。仅 UI 显示缓冲，不改 runtime 100ms 发布与保存节奏。

跟随时 cell 高度正常更新，display link 以临界阻尼将 offset 追向底部；新目标承接当前位置和速度，小积压限速、大积压连续加速，不重启动画、不按内容类型分支。用户拖动即停，非跟随不动画；没有另做容器高度/裁剪过渡或逐词淡入。

系统或应用减弱动态开启时，停用显示缓冲和追随动画，直接显示并贴底；VoiceOver label 使用已显示内容，不提前朗读。逐词淡入仅是[暂缓候选](../engineering/performance.md#ai-列表第二步与显示候选)。

## 检查口径

跟随收敛后 gap≈0；非跟随及加载更早时锚点误差≤2pt，无空白帧。胶囊显隐扣除新增/移除 inset 高度 H 后误差≤2pt，inset 与 overlay 同帧变化，不先跳再回。新末行从上一行下方、输入区上沿随 offset 进入，不先出现在可读区再被推走。

小积压≤约3行时单帧位移≤1/3行高；大积压不设固定400pt/s上限，单帧≤有效视口1/8、积压≤约半视口，无反向/瞬移。结束约350ms收敛，自动断言≤400ms容差，原值照记，不为容差改曲线。显示落后权威文本目标约300ms以内。回放分别用每100ms 5–15汉字普通流和20–80字密集结构流，覆盖工具插入、列表/代码/表格、队列换轮、上翻结束、键盘和搜索定位；性能比较 Release 首屏、分页追加、RSS与长帧，不以单次平均值代替真实手感。

## 每轮回复的展示

- 运行时直接展示中间回复；两段普通回复（或补充消息）之间连续的推理和工具调用归为一组，默认收起。组标题显示当前活动，完成后显示动作摘要与调用数量；单个活动直接用一行呈现。
- 推理标题直接预览服务返回的文本，单行尾部省略，展开看完整内容；使用 `sparkles`。真实 reasoning-start 事件尚无文本时显示“思考中”，没有推理事件的请求等待显示“等待回复”，不补造推理。
- 分组、推理条目和工具条目分别按真实运行状态显示系统小型 ProgressView；完成、失败、停止、等待确认均停止对应加载动效。减少动态效果使用静态沙漏。
- 工具行轻量呈现图标、动作和状态，点击打开详情 sheet 查看参数与结果；来源预览入口放在相应结果内，不在最终回复下重复列工具来源。
- 过程文字统一一个层级：`.subheadline`、主题次要文字色；正在进行的分组或条目标题改用正文色（分组标题加中等字重），失败用危险色；“查看过程”与之同级。紧凑行高 32pt、条目间距 4pt，整轮过程、活动分组与推理全文统一使用原生 DisclosureGroup，箭头与内容展开由系统处理；完成工具不逐行重复“已完成”；加载、异常和部分结果保留状态。组标题使用简短类别，避免串联全部工具名称。
- 当前页完成时过程保持展开；重新打开时已完成轮次折叠为“查看过程”，用户可展开，最终文本块身份保持。见[消息呈现](rendering.md)。
- 失败、停止、等待确认时默认保留过程。已经收到的部分回答和已完成工具结果保留；错误行位于该轮末尾、过程折叠之外。
- 工具失败显示在相应调用上，模型可以继续处理；不能将一次工具失败直接等同整轮失败。模型请求失败才显示本轮请求错误。
- 错误不遮挡输入框，也不阻断返回阅读。状态必须来自真实事件。

## 请求失败后继续

请求失败后，在本轮末尾显示简短、安全的原因，例如网络中断、请求超时、认证失效或额度不足；不能可靠识别时显示“请求未完成”。保留已经显示的内容与工具过程，输入框照常可用。

不放重试、重新登录、切换模型、错误详情等配套按钮，不做倒计时或专门恢复流程。用户自行处理网络或连接问题，需要时通过已有入口换模型，再发送“继续”或其他消息。

“继续”是普通 user 消息，沿用同一对话的正常发送与 Agent 循环；不解析为特殊恢复命令，不自动重放上一轮，不保证从失败的 token 或工具步骤断点续传。已有消息和工具结果按正常协议投影，模型自行决定后续动作。普通网络/API 失败不新增自动重试。已有输入超窗压缩策略独立处理，不扩展为通用故障恢复。

错误原因来自可靠的网络错误类型或供应商结构化错误，不展示原始响应、凭证、请求体或小说原文。不能把所有 429 都认定为额度不足，也不能把所有失败都要求重新登录。停止、拒绝及工具失败继续保持各自语义。


## 正文准备确认

卡片显示具体书籍、待执行动作（下载、解析或两者）及已知大小；未知大小不编造。卡片为 `surface` 底、1pt `border`、16 圆角，原因用次要文字；主按钮“准备正文”使用主题实心按钮（accent/onAccent），次按钮“暂不准备”为普通描边按钮，空间不足时纵向排列。执行前重新校验对象及文件授权。

批准、拒绝、停止与重启的业务语义由[Agent 确认](agent.md#确认准备与恢复)定义；界面只发出操作并展示实际状态。

不增加“始终允许”、权限管理页或通用授权中心。文件夹的系统访问授权继续由现有文件服务处理，与这次准备确认分开。后续资料/书架方案的确认应用遵守各自业务契约，不扩展为模型可直接写入的权限。

## 对话容器

标题栏与消息区使用所在作用域的不透明底色：对话 Tab 为 App `canvas`，阅读弹窗沿用阅读作用域，与其他阅读弹层同为 `surface`；不另设 AI 配色。

- 用户消息靠右、按内容收缩宽度，`accentSurface` 底、正文色、16 圆角；常规字号左侧至少留 48pt，辅助功能字号缩到 16pt，长中文与大字号仍可舒适换行。消息附带的阅读附件以次要色小字列在气泡内。
- 回复不加底框，直接显示 Markdown；复制按钮与“已停止/回复已中断”位于回复下方同一行。轮间距 24pt，轮内 12pt，左右页边 16pt。
- 输入框为 `surface` 底（阅读弹窗用 `raised`），1pt `border`，聚焦时改为 `focus` 色，20 圆角。发送与停止为 accent 实心圆配 onAccent 图标，不可发送时为 `selected` 底与次要色图标；`+` 与发送方式菜单的触区不小于 44×44pt。供应商图标保持原色。
- 待发送附件为 `input` 底、8 圆角的小签，按宽度换行排列，长摘要中间省略，`×` 只移除该项；小签与 `×` 的点按区域均不小于 44×44pt，只在其中绘制较矮的底色，相邻触区不重叠；排队消息位置不变，使用 `input` 底与描边。
- 请求失败由运行器状态和历史映射，显示在对应轮次末尾；保存、提交、删除等临时操作失败用原生可关闭弹窗通知，不保存为对话错误、不常驻输入框上方。
- 工具详情不显示 UTF-8 起止位置、上下文偏移、读取上限及内部引用等坐标字段；“查看原文”等来源跳转保留。

消息区域使用原生交互式键盘收起，空对话也允许下拉；点击消息区域可解除输入焦点，不清空草稿，点击手势与子项操作同时识别。离开底部时显示居中的圆形向下按钮，点击回到底部；滚动几何判断位置，用户查看上方消息时不被流式输出强制拉回。
