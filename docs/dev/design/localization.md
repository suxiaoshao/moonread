# 国际化与本地化

状态：已有简体中文/英文 String Catalog，阅读工具、批注编辑器、即时错误映射和主题设置文案已接入。设置页 显示 App 语言并打开系统设置，语言遵循系统的单 App 选择。导入错误保存类型与参数、展示时翻译；数量文案使用英文复数资源。完整界面验收边界见[验证记录](../engineering/verification.md#待完成的验证)。

## 语言与原文约定

- 当前支持简体中文和英文资源，遵循系统为 App 选择的语言；设置页语言按钮已接入系统 App 设置。
- 覆盖书架、阅读工具、设置、空状态、准备/暂停/失败状态、提示、按钮和无障碍标签，不能只翻译可见页面标题。
- 时间、数字、百分比和数量表达使用当前语言区域的格式；复数和带参数的句子交给本地化资源处理，不拼接已翻译的零散词语。
- 书名、文件名、目录名、章节标题和小说原文按原样显示。界面语言变化不翻译小说、不触发重新导入，也不改变阅读位置。
- 更多语言在后续增加；布局从现在起使用语义方向、允许文字伸缩，为长译文和后续从右向左语言留出适配空间，但不把未验证语言声明为已支持。

## 平台与核心分工

| 层次 | 职责 |
| --- | --- |
| iOS | 使用 Xcode String Catalog（`.xcstrings`）维护本地化资源，Swift 负责按当前语言呈现界面、格式化数值及无障碍说明 |
| Rust | 返回稳定的领域错误类型/错误码和结构化参数；保存跨平台状态，不把面向用户的中文句子当成 UI 契约 |
| 后续 Android | 将相同领域状态映射到 Android 本地化资源，复用 Rust 业务逻辑，不依赖 Swift 的资源类型 |

错误本地化必须覆盖导入任务保存的失败状态和重新打开后的提示，不能只转换即时抛出的异常。内部诊断与用户说明分开：UI 根据错误类型给出原因和可执行的下一步，原始系统错误只作必要补充，不直接作为主要文案。

`import_jobs.error` 保存带 `kind` 的 `ReaderError` JSON（当前 schema 版本见数据专题），保留诊断参数。`ReadingSnapshot.error` 和 `failImport` 使用同一领域类型；即时和重新打开后的失败都经过 `ReaderMessages`，按当前 App 语言给出用户说明。文件协调错误保留系统 domain/code，不保存已本地化的说明。暂停不保存错误，重试清除旧错误。后续持久化格式演进须提供版本与迁移测试。

资源继续以简中文案为 key，保持 SwiftUI 字面量的自动提取，不做全量英文 ID 替换。同文不同义时使用语义 key 和明确的默认文案；易歧义的短标签、插值参数在 catalog 中写翻译注释。Swift 携带普通 `String` 时必须先本地化；带参数提示与无障碍标签使用完整插值句子。

英文的项目、结果、连接、调用、文件、阅读日等数量使用 catalog 的 `one/other`。一句中有多个独立数量时使用 substitutions 分别复数化，书架位置和搜索范围等文本参数保持原顺序语义；数字、百分比及简写单位沿用区域格式。

本地化资源与 Swift UI 一起维护，不在 Rust 中引入 iOS 字符串资源或平台 `Locale` 对象。语言入口优先利用系统的单 App 语言能力；具体入口需按支持的系统版本核对，避免系统语言设置与应用内覆盖互相矛盾。

参考：[Apple String Catalog](https://developer.apple.com/documentation/xcode/localizing-and-varying-text-with-a-string-catalog)、[SwiftUI 本地化准备](https://developer.apple.com/documentation/swiftui/preparing-views-for-localization)。

## 验证标准

- 简中和英文下走完选择目录、开书、阅读、展开工具、设置、暂停/恢复及返回书架；正常状态和错误状态均无遗漏的固定中文文案。
- 英文较长文案、较大系统字号下，按钮和状态提示不互相挤压；阅读工具不因译文长度覆盖额外正文或改变阅读位置。
- 切换界面语言后，书名和正文保持原样，已有书籍、模式、主题和进度保留。
- 时间/百分比/数量遵循区域格式，VoiceOver 标签与可见语言一致。

这些检查结合现有浅深外观与导航场景进行，已有证据见[验证记录](../engineering/verification.md)。完整应用验收仍未完成，不能把阅读工具接入资源视为全应用本地化已完成。
