# 首次使用与引导

四步开场、使用指南、三条 TipKit 提示和空书架引导已实现。真实 iCloud 与设备验证范围见[验证记录](../engineering/verification.md)，不能由注入的登录状态推断真实云同步通过。

## 四步开场

首次打开全屏分页，每页一个主题；底部主操作“继续”，欢迎页为“开始”，后续页可返回。不提供跳过全部。缺少本机 `Moonread.onboarding.completed.v1` 标记的安装走一次引导，包含重装。

1. 欢迎：应用图标、名称和阅读定位。
2. 存储：账户可用时说明固定 iCloud 书架，并默认勾选阅读数据同步；不可用时说明本机存储和以后启用方式。不提供书架根位置选择或文件 iCloud 开关。
3. 可选 AI：默认关闭，不在引导填写连接或密钥；入口遵守地区可用性。首次内容发送仍需独立许可，见[AI 产品规则](ai.md)。
4. 开始阅读：导入第一本书或读原创示例《月光下的归途》。已有书时显示“打开书架”。选择即完成引导；取消后续文件选择器不反复弹引导。

第二、三步的选择保留到最后一步统一提交：先同步保存本机同步意愿，再写完成标记；后台初始化 CloudKit，不阻塞进入 App。全屏引导关闭后再打开选择器/阅读器，不同时替换导航和弹层。

示例仅在内置目录确认为空后写入。云端首次发现未完成不能写示例；已有内容直接进入书架，不等背景发现。目录读取失败后允许打开书架，不反复尝试放示例。复制后的扫描如被接管，等新扫描发布后按相对路径标记示例，不能误计为用户导入。

四页使用相同导航区域与图标顶距，切换步骤回到内容顶部。底部同色、四个步骤点；大字号内容可滚动，最后一页只固定操作按钮。发现等待约一秒后才显示轻量文字/进度；离页取消。支持主题、三语、动态字体和 VoiceOver。

## 使用指南与一次性提示

指南是独立原生说明页，不进入书架，不借阅读器显示，不读写进度、最近阅读或统计。入口在设置和内置根空态；文案以 `Localizable.xcstrings` 为准，功能变化时同步核对，不在文档另存整份副本。

引导完成后才允许 TipKit 提示；最多同时一条。提示显示过、关闭或相应操作已完成后不再出现。

| 位置 | 条件 | 提前失效 |
| --- | --- | --- |
| 书架“＋” | 没有用户导入的书且从未导入 | 成功导入或关闭 |
| 阅读工具 | 首次进入书籍，工具隐藏 | 显示工具或关闭 |
| 长按选字 | 已显示工具且从未选字 | 选字或关闭 |

只用这三条，新增先修改本表。提示跟随所处 App/阅读主题，使用 surface/ink/secondary，名称本地化；AI 相关文字遵守可用性。不用提示遮挡正文或引导页。

## 空书架

内置根确认空时显示“还没有小说”，提供导入与指南；子文件夹/外部根保留空文件夹语义。云发现未完成显示发现状态，不先闪空。已有书不被背景加载遮住。目录状态必须使用下面的共同来源，不能由页面另猜“云端为空”。

### 架构：沿用内置根发现状态

[CloudDocumentQuery](../../../ios/Moonread/Library/CloudLibrary.swift) 区分首次 gathering 完成与增量更新，发布带代次、revision 和 gathered 的快照，并处理查询启动失败。内置根使用 `notRequired / discovering / ready / unavailable`；只有采用快照并读回对应目录后才进入 ready。开场引导与文件夹页使用同一个目录读取确认入口，不另外判定云端是否为空。

`homeReady` 仅保证本地首页快照，`cloudLibraryUpdating` 表示根交接，`CloudStore.status.syncing` 表示 CloudKit 用户数据同步，三者均不能替代 iCloud Documents 初次发现状态。发现状态只控制空的内置根，不扩展为全应用同步状态机。

1. 在首次本地首页/内置根发布前就确定是否需要云发现，避免 `library.load()` 完成后才由 `cloud.refresh()` 启动查询而留下闪空间隙。无 iCloud 账户/构建不支持时为 `notRequired`；存在账户但容器或首次查询尚未完成时为 `discovering`。已有可显示条目直接显示，不因背景发现遮住内容；状态只控制空的内置根，不影响子目录或外部书架。
2. `CloudDocumentQuery` 区分首次完成与增量更新，连同 items 发布代次/revision。根接入成功、首次 gathering 完成、采用该快照的内置目录扫描及页面 reload 成功后，才发布对应的 `ready`。不要先把状态改 ready 再异步扫目录；否则仍会短暂显示旧的空 entries。空结果也必须完成这次状态发布，不能被 HomeSnapshot 等值去重吞掉。
3. 页面以“目录确实为空 + 无目录错误 + 发现状态为 ready/notRequired”显示“还没有小说”。发现中的空根显示已有轻量加载反馈；失败、账户变化、`query.start()` 失败或等待过久显示“暂未完成发现/重试”一类中性状态，并保留导入和指南入口，不把超时当作云端为空。账户/根变化重置代次，忽略旧任务结果。后续增量更新静默应用，不把已经显示的非空目录反复切回加载页。
4. Apple 的首次 gathering 完成只表示**当前元数据索引的首轮匹配结果已收集**，之后仍有 live updates；它不能证明服务器上永远没有其他文件。实现和文案应承诺“不在已知发现过程未完成时先显示空”，不承诺一次回调证明云端全量同步结束。[Apple：NSMetadataQuery 两阶段](https://developer.apple.com/documentation/foundation/nsmetadataquery)、[iCloud 文档发现示例](https://developer.apple.com/documentation/uikit/synchronizing-documents-in-the-icloud-environment)

涉及 `Library/CloudLibrary.swift`、`Library/LibraryService.swift`、`Library/LibraryModel.swift`、`Library/LibraryView.swift`，以及 `Settings/CloudStore.swift` / `App/MoonreadApp.swift` 的启动与账户变化接线。全局启动遮罩继续只等本地首屏，不延长到云发现完成。

模拟器注入可控发现源，覆盖：首次结果延迟但最终非空、首次结果为空、结果已到而扫描仍在途、启动失败/超时、旧账户迟到回调、已有本地内容时云发现未完成。使用真实 LibraryModel→页面状态链路断言无空状态中间帧。现有 `--ui-testing` 会关闭真实云能力，所谓“模拟登录”应明确为依赖注入，不能当作真实 iCloud 账户或服务时序验收。


## 验收边界

保护引导选择保存、取消、发现未完成不写示例、过期结果不发布、示例不计导入。测试职责见[验证原则](../engineering/verification.md)，不复制系统 TipKit 行为测试或语言/外观排列矩阵。真实云发现与真机最终试用单独记录。
