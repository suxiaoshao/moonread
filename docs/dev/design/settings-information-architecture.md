# 设置信息架构与新增入口规则

更新：2026-10-25。状态：1.3 设计依据。界面整理已落实 V2 B、V3、V5 A 与 V6 设置 B；V1/V4 和 V6 阅读 A 仍待实现。本页规定信息归属，不因效果图而复制设置、变更默认值或增加持久化。

当前入口与行为见 [设置页](settings.md)，规则归属与兼容要求见 [架构](../engineering/architecture.md)，同步边界见 [数据同步](../data/sync.md)。

## 当前组织的评价

`SettingsView.swift:36–112` 目前的分节——阅读、书架与数据、AI 助手、外观与语言、帮助与关于——总体合理，继续保留。书架、统计及书内的就近入口进入同一个设置页/model，避免让用户在多个地方改同一个偏好。

已经合理的部分不重做：

- 阅读统计开关、暂停说明、历史清除在同一个子页，清除独立分节；“同页”不等于危险操作没有隔离。
- 书架管理拥有目录授权与自动索引；数据管理拥有备份、阅读数据删除与缓存清理；iCloud 拥有同步开关、状态和账户/文件冲突。这三页不因都涉及“数据”合成一个大面板。
- App 外观与阅读纸面分别在应用外观、阅读设置，语言跳系统 App 设置。阅读预览复用实际偏好，不另存“预览配置”。
- AI 默认使用、连接与能力属于同一个领域；本轮按 V2-R A 使用默认用途与连接原生分组，但不把各服务商或模型都变成首页入口。

主要增长风险是：每增加 Spotlight、Widget、编码同步就各加一个首页开关；按实现模块而非用户任务归类；把状态和错误也当设置项；宽屏为左/右两栏各维护一套设置状态。下面的规则用于避免这些问题。

## 分组与层级原则

1. **一个持续偏好只有一个归属页。** 以用户想完成的任务分组，不按 Rust/Swift、CloudKit/WidgetKit 等实现分组。其他页面可以有快捷入口，但进入同一配置与保存流程。
2. **设置、动作、状态分开。** 开关改变持续行为；导入/导出/清除是任务按钮；同步中/失败是任务状态；说明在相关 footer。没有可选择行为就不给一个“已开启”开关。
3. **首页负责找入口，不承载所有配置。** 首页常见行显示一句真实摘要；细项集中在任务页。一般是“设置 → 任务页 → 具体对象编辑”，不为一条说明再加一层页面；对象多时仍用列表。
4. **控制范围优先于技术名称。** “阅读数据 iCloud 同步”与小说文件同步必须分清；“本书编码”只影响当前原始字节对应的文件；“在此设备记录统计”不冒充全设备开关。说明本机/同步范围，不能靠用户猜。
5. **相关操作就近，危险操作单独。** 开关与清除历史同页，但清除放独立区域、保留确认与范围；恢复与丢弃不能并列成同权重主按钮。一个任务区只突出一个主操作。
6. **默认行为不是一个待确认问题。** 用户已定的默认开启能力不加 onboarding 或隐私弹层。只有会实际发送数据、账户切换、文件覆盖或删除等原有边界保留确认。不能用“保护隐私”默认隐藏本机书名/进度。
7. **未实现功能不占位。** 不新增灰色朗读、通知等菜单；搜索设置、后台刷新周期、迁移 epoch、SHA、缓存协议版本等实现参数不进入 UI。
8. **持久化只在原 owner 写一次。** 小组件配置由系统 Widget 配置持有，App 只展示说明；iCloud 关闭不阻止本机编码保存；宽屏和窄屏共享同一 model、草稿、选择与失败恢复。

首页增长时先问：能否归入现有任务页？是否只需一段说明或一个就近动作？是否真需要用户长期选择？只有新增了独立、可理解的任务领域，才增加一级入口；不预先做设置搜索、插件式配置注册表或动态分组机制。

## 1.3 首页分组与顺序

保留现有分节和顺序，**只新增“系统集成”一行，放在阅读组末尾**。这是“从系统接着读/找书”的统一入口，不把 Siri、系统搜索和每种 Widget 分散到首页。

| 分组 | 首页顺序与摘要 | 子页职责 |
| --- | --- | --- |
| 阅读 | 阅读设置（上下滚动/左右分页）；阅读统计设置（记录中/已暂停）；**系统集成（系统搜索、快捷指令、小组件）** | 阅读设置含排版/配色/纹理/屏幕控制与预览；统计页含记录与清除；系统集成页见下一节 |
| 书架与数据 | 书架管理（数量）；数据管理（备份、恢复、清理）；iCloud（阅读数据同步状态） | 授权与索引；备份/删除/缓存；阅读数据同步与小说文件状态分别负责 |
| AI 助手 | AI 功能总开关；可用时进入 AI 助手 | 连接行、默认用途三行、共享的按连接分组、始终可搜索的选择列表，点选即保存返回；对话浮层用共享强度滑杆。国区只读限制说明；总开关隐藏入口的既定规则保持 |
| 外观与语言 | 应用外观（当前明暗）；语言（当前语言 · 系统设置） | 只控制 App 外壳与语言；正文偏好不移到这里 |
| 帮助与关于 | 使用指南；给月读评分；关于月读；支持月读 | 帮助、许可证和可选打赏；不放阅读中需要频繁操作的工具 |

系统集成页不是新的 Tab；设置始终占 Tab，系统集成归入阅读组。不能把 Siri/App Intents 视为月读可选 AI 助手，因此国区仍可使用这些已支持的系统入口。

## 1.3 新能力具体放在哪里

| 能力 | 用户入口与呈现 | 持续选择/存储 | 明确不增加 |
| --- | --- | --- | --- |
| #16 系统搜索 | 设置 → 阅读 → 系统集成 → “在系统搜索中显示书籍”及“排除的书架” | 本机开关默认 true；排除默认空。同 SHA 任一已知副本被排除则不索引/捐赠 | onboarding 选择、全库自动下载、正文索引 |
| #11 自动续读建议 | 同页系统搜索说明中写明“读过的书可出现在系统续读建议中” | 与系统搜索/书架排除共用展示范围；只为真实读过的书捐赠 | 单独的 donation 技术开关、按页捐赠、向 AI 发正文 |
| #11 Siri/快捷指令/按钮 | 系统集成 → “Siri 与快捷指令”footer 说明五个动作：继续阅读、我的书架、搜索书籍（可选关键词）、阅读统计、打开书籍；提供已支持的系统入口/说明 | 快捷指令由系统保存；明确选书不受 Spotlight 自动索引开关限制 | App 内再造快捷指令编辑器，或只为说书名/时长加隐私确认 |
| #12 小组件 | 系统集成 → “小组件”简短示例/添加方法；具体最近阅读/指定书在系统 Widget 配置选择 | 用户自行添加，桌面续读/最近阅读/统计，锁屏/待机默认书名+进度，自设封面缺失时文字回退 | App 内总开关、隐藏详情开关、同步 Widget 布局、自动添加小组件 |
| #98 同步位置提示 | 阅读器内的非打断提示，8 秒后收为工具入口，可跳转/留在这里 | 本机基线和当前会话状态，既有云位置 LWW 不变 | 阈值滑杆、超时设置、另一个同步进度开关 |
| #99 编码选择 | 阅读中 → 阅读设置 → 本书 → 文字编码；打开失败仍走现有编码恢复入口 | 按 rawSHA 保存 UserValue；跟随阅读数据 iCloud 同步，无 key=auto | 首页编码入口、编码同步开关、“使用并同步当前编码”按钮 |
| #99 同步说明 | iCloud → 阅读数据同步 footer 增加“手动选择的文字编码” | 仍使用现有阅读数据开关及账户确认 | 独立编码 CloudKit 配置页、向用户展示迁移队列/epoch/token |
| #103/#110 宽屏 | 阅读器与阅读设置依据可用空间安排正文、工具；设置两栏见 V6 | 已存在偏好与页状态共享；需要新增的可选布局选择先由 V6 定 | “Duo 模式”开关、按机型名称分支、独立平板设置副本 |

系统集成子页只需三个任务区：

- **系统搜索与建议**：开关、排除的书架、简短范围说明。说明“只使用已识别书籍的书名、作者和标签，不索引正文”。关闭会移除相应索引和自动建议，但不删书或阅读记录。
- **Siri 与快捷指令**：可用动作和系统配置说明。Siri 可以说“正在打开《X》”，也可直接回答今天/本周时长；系统限制导致数据不可读时如实提示。
- **小组件**：真实内容结构的合成预览及添加方法。画廊继续用合成书名；用户添加后呈现实际书名与进度。不增加仅用于确认展示自己数据的开关。

书架排除是系统搜索/自动建议的设置，不阻止 App 里打开书，也不禁止用户明确在 Widget/快捷指令配置中选它。数据离开原来的界面不等于请求月读 AI；原有外部发送许可、CloudKit 边界和正文不进系统索引的约束保持。

## 设置宿主（方案 B）

设置始终占 Tab。根 `NavigationSplitView` 的 sidebar 使用现有完整分节条目，AI Toggle 和外部动作仍在目录内；regular 为系统侧栏，compact 保持 release/1.3 分组表单。点击任务后右侧直接显示对应页面，分节仅作标题，不增加分组导航、任务条或第三列。

scene 的唯一 `SettingsNavigation` 保存当前任务、详情路径与配色草稿。阅读偏好读写统一走 App 级 `ReaderSettingsStore`，书内和设置页共用当前值与串行保存。任务内部由固定详情 `NavigationStack` 钻取；宽屏首次可选阅读设置，手机首次停完整首页，折叠/旋转/切 Tab 不主动清路径或草稿。不写手工折线几何、不在宽窄分支各建宿主。手机的阅读设置及其他任务内容、标题、Tab 隐藏和预览都保持 release/1.3。

全局就近入口定位设置 Tab 的任务，书内更多保留 ReaderSession 边界。语言、评分等外部动作不成为右栏 selection；没有独立的“返回书架”按钮。

## 未来新增设置的落点示例

| 新需求 | 先放哪里 | 何时才需要首页新入口 |
| --- | --- | --- |
| 阅读排版、翻页、正文显示 | 阅读设置对应排版/页面/控制分区 | 仅成为独立任务且现有页明显无法容纳时另评估 |
| 目录来源、下载/索引策略、外部授权 | 书架管理；针对单书的恢复操作放单书旁 | 不因增加一个文件提供方多一个设置入口 |
| 备份格式、缓存清理、删除用户数据 | 数据管理相应任务页 | 不增加与数据管理重复的“存储/隐私”总页 |
| Siri、Spotlight、Widget、后续系统动作 | 系统集成的相应任务区 | 新平台独立能力确有大量设置时再拆子页 |
| 同步新增一种用户事实 | iCloud 范围说明，事实本身在对象编辑处 | 不默认每类数据增加一个同步开关 |
| AI 新服务商/模型/用途 | AI 助手连接分组或默认使用 | 不在设置首页按服务商分组 |
| 将来朗读或提醒（未实现） | 先按实际阅读/提醒任务设计 | 不预留灰色行；不因系统有 API 就增加设置 |

## 实施与文档维护

本页是 1.3 的设计合同，当前已实现入口仍以 settings.md 的“当前设置内容”为准。实现 PR 更新后，两者应一致；不要把未来方案提前写成已上线行为。

新增设置在 PR 描述说明：用户任务、归属页、适用范围、本机/同步、默认值、旧数据兼容、是否有就近入口；这些是实现决策，不把这张技术表塞进产品 UI。测试保护自己的状态与保存边界，不测试系统菜单、Widget 刷新时机或 Siri 识别质量；宽窄和长文本以实际画面验收。
