## 本机 AI 总开关

设置中的“AI 功能”默认开启，使用独立版本化本机 UserDefaults 键 `Moonread.ai.enabled.v1`，不进入 CloudKit。关闭即隐藏 AI 设置/连接与 ChatGPT 登录、对话 Tab 和对话搜索结果、阅读月亮（包括选区提问）、详情资料/封面任务、书架整理/多选/单项资料入口及统计分析；联网搜索与图片生成用途随 AI 设置隐藏。指南隐藏 AI 章节，选字指南与 TipKit 改用不含 AI 的文字。

`AIService.availability` 是界面与执行的唯一政策来源。关闭会使执行租约失效、取消对话提交和 agent、登录、目录刷新、原生搜索/生图及待确认共享请求；执行层拒绝新请求，重新开启也不会复活已取消的任务。停止尚在收尾时新发送的输入先持久化，旧运行退出后自动接手且仅消费一次；再次停止或关闭会撤销接手请求，交接时仍检查总开关。读取本地历史允许继续，以便开关不改变数据。连接、会话、Keychain 凭据、默认用途和既有共享许可均保留，重新开启后恢复原有入口与配置；后续地区限制应接入同一可用性来源。

## 内容共享许可

首次内容发送前，由 AIService 拥有的 AIDataSharingConsent 按实际接收方、协议／规范化端点、账户代次、告知版本和数据范围询问。记录只在本机 UserDefaults 保存，不存内容或凭据、不进 CloudKit。发送前预检保留草稿与附件；拒绝不创建运行。恢复、每步请求、自动摘要及独立搜索／生图在实际配置解析后再次校验，同意聊天服务不代表同意另一家的原生服务。仅换模型而接收方与范围相同不重问。

确认页由当前聊天或快捷任务 sheet 承载，显示真实域名、用途、历史／附件／可用工具读取范围及第三方保留／额度说明。找封面还告知结果网页／图片站点接收 URL 请求与 IP。连接认证和模型目录请求另作非内容说明。停止、删除、拒绝或离开承载页会取消等待；同范围的并发请求复用许可但分别校验 owner。运行时的等待状态不持久化。

连接详情可撤销许可，立即停止该连接的内容任务；已发数据不能追回。更换凭证、退出、删除、供应商／协议／端点变化使旧许可失效，不由已有 Key 或历史推定同意。政策链接目前采用待发布候选，正式发布前须可访问。

## 入口与对话

- 首页增加独立“对话”Tab，排列为书架／对话／统计（设置在书架首页齿轮，搜索为尾侧独立入口），集中查看和继续历史对话；Tab 使用标准对话气泡 `bubble.left.and.bubble.right`，阅读页的月亮是助手形象与入口。
- 阅读页点击正文唤出操作层时，同时出现月亮按钮；点击月亮打开小型对话弹窗，可展开长聊、新建或选择之前的对话。关闭返回原阅读位置，不改变正式续读位置。
- 选区、详情、书架和统计提供带上下文的入口或快捷任务，复用同一对话与工具能力。
- 页面信息是当前待发送用户消息的结构化附件，不是不可移除的会话前缀。发送前可查看、移除或用 `+` 添加其他对象；发送后保存为该条消息的一部分。会话关联书籍用于历史查找，不自动作为隐藏的模型输入。
- 不设强制剧透限制或按阅读进度封锁工具。提供当前位置给模型，由模型结合用户问题判断；用户可以直接询问后续剧情、结局并读取后文。用户明确要求不剧透时应遵从，但不把它实现为统一进度闸门。

## 不同入口的上下文

| 入口 | 默认上下文 | 典型用途 |
| --- | --- | --- |
| 阅读页 | 当前书、章节、阅读位置 | 问剧情、找伏笔、解释人物、回顾前情 |
| 文本选区 | 选中文字、所属书与原文位置 | 解释、翻译、关联前后文、批注建议 |
| 小说详情 | 当前小说信息及正文身份 | 补全作者、简介、标签，查找或生成封面 |
| 书架目录 | 当前目录；多选时带选中项目 | 找书、推荐、分类、批量整理 |
| 统计页 | 选定时间范围；单书页带当前书 | 阅读习惯分析、比较近期阅读、查询记录 |
| 对话 Tab | 新输入默认无页面附件；历史仍保留已发送内容 | 延续任务，用 `+` 主动添加阅读对象 |

默认提供完成任务所需的有限上下文，后续按需读取，不自动上传整本小说。待发送附件及工具实际查询范围应可见；阅读位置属于理解问题的上下文，不代表用户已读完当前位置前的所有内容。

## 对话骨架与阅读附件（2026-10-03）

首页完整对话与阅读 medium/large 弹窗复用同一组件和同一标题菜单：标题右侧带下拉箭头，菜单首项“新对话”，其后列出已有对话并勾选当前项。完整对话右上角另有新建按钮；阅读弹窗右上角只有关闭 ×。底部输入框保持可达，键盘弹起时随安全区上移。完整对话收起首页 Tab 栏。输入框按内容增高到上限后内部滚动。消息与过程的版式见[对话错误与单次操作确认](../ai/errors-and-confirmation.md#对话容器)。

普通全局对话以首次发送的用户消息前40个字符作为标题，与首次列入列表、首条发送队列同一次保存；后续消息不改标题。书籍关联和快捷入口既有标题保留。AI 自动生成标题暂缓，不产生额外供应商调用。

输入框内部顺序：结构化附件摘要、用户文字、`+`／紧凑模型与思考入口／发送。模型入口按既定规则点击后展开；运行活动显示在对应过程分组中；运行时空输入显示停止按钮，输入文字后显示发送（默认 steering），菜单可选 follow-up。发送提交任务存在时禁用输入、附件、模型及发送/follow-up，完成或失败后恢复；不按内容去重，提交后允许再次发送相同文字。队列有内容时才显示，可移除未消费项。不添加常驻教学说明。

### 对话搜索的当前语料与定位

2026-10-07 源码核对：以下记录当前行为，语料范围和命中定位留待后续讨论；本次搜索页面复用不修改它们。搜索入口与页面行为见[找书与搜索](library.md#找书与搜索)，对话 Tab 不另设搜索框。

只搜索对话列表中已列出的会话。标题匹配独立于历史消息匹配；草稿和未列出的快捷任务不参与。作者、标签或书架筛选生效时，结果不包含对话。

| 内容 | 当前搜索规则 |
| --- | --- |
| 对话标题 | 匹配标题 |
| 已消费并保存为历史记录的用户输入 | 只取 `userText`，包括初始提问、steering 和 follow-up |
| 没有任何工具调用部分的助手消息 | 取文字部分和 `content.value`，不检查是否最终回复、结束原因或完成状态 |
| 已保存的中断回复、被后续回答移入过程的较早助手正文 | 满足上一条时仍可搜索 |
| 带有工具调用的助手消息 | 整条消息不产生搜索文字，连同可读的说明文字也排除 |
| 思考内容、工具调用与输入、工具结果与结果卡片、system 消息 | 不搜索 |
| 附件及给模型展开的上下文、模型名 | 不搜索 |
| 尚未消费的排队输入、未提交的流式文字、未发送草稿 | 不搜索 |

“过程”是显示分组，不是搜索分类。助手回答后消费 steering 可以继续同一轮：较早的纯文字回复和后加入的用户输入会显示在过程中，但各自的搜索文字仍保留。过程中的思考、工具内容和伴随工具调用的文字则不参与搜索。语料提取与持久化规则见 [Agent 历史存储](../ai/agent.md#消息持久化与分页)。

每个对话只显示一行，按最近更新排序，使用最近的命中历史消息生成摘要（“你：”或“月读：”前缀、命中词强调）。只有标题命中时不显示消息摘要，也没有消息定位锚点。

点按有消息命中的结果后，加载以该消息结尾的一页和其后一页，随后按整轮对话居中并短暂高亮整轮；当前没有按独立消息或命中文字范围定位。长回复中的命中位置可能不在屏幕内，完成轮次折叠的“查看过程”也不会因命中自动展开。因此，过程中的用户文字或较早助手正文虽然可搜到，打开后仍可能隐藏在折叠区。

上方沿用“加载较早消息”，下方显示“加载较新消息”，“回到底部”或发送新消息回到最新一页继续实时输出。窗口停留在较早历史时，新的实时条目不插入该窗口。后续讨论项为语料范围、命中文字居中与高亮，以及隐藏命中的展开方式；这次只记录现状。

### 阅读附件

`+` 本轮只提供“书籍”“书签”“批注”；不提供照片、相机和通用文件附件。选择已有阅读对象，使用同一附件结构；每次显式添加产生独立出现项，同一对象可重复添加，允许不同书籍并存。书签和批注选择可按书籍定位。取消选择不改变草稿，不自动准备或上传正文。

附件摘要示例：`《云海拾光》· 第一章 · 12.3%`、`选中文字 · 24字`。摘要可点开预览，右侧 `×` 只移除待发送项。多个附件换行排列，不能挤压发送与模型入口。详情预览展示书名、章节、进度、选文或所选批注内容；内部 SHA 和字节坐标不作为常驻产品文案。没有选文时不留空卡片。

### 数据契约

每条消息保存 `text` 与 `readingAttachments[]`。附件有独立 `id`、`kind`（book/position/selection/bookmark/annotation）、`origin`（入口页面）、`capturedAt`、`bookRef`/正文 SHA 和 `titleSnapshot`。位置附件另含：

- `chapterRef?`、`chapterTitleSnapshot?`；
- 当前可见原文范围 `visibleRange:{startUtf8,endUtf8}`，区间为 UTF-8 字节 `[start,end)`；
- `progress?`：0–1 的全书进度快照，未知则省略；
- `pageSnapshot?`：仅现有分页模式已提供时附带页码及其分页范围含义；不为 AI 另算页码，不作为稳定定位依据。

选区使用 `selection:{text,startUtf8,endUtf8}`；批注/书签使用稳定 `objectRef`、正文范围及已选对象内容快照。批注存在冲突时保留该状态，不伪造最终评论。每个附件自行携带书籍身份，移除位置卡不会让保留的选文丢失定位。

从阅读页唤起自动生成位置附件；有选区时另附选文；从具体批注或书签唤起再附相应对象。小说详情页附书籍身份与已有资料摘要。只提供当时选中的对象，不自动塞入全书批注、书签或正文。源文件未准备时使用已有 fileRef 和名称，不猜 SHA，不因打开对话自动下载。

发送前可以移除所有附件，得到普通文字输入；这不删除历史中已经发出的附件。发送时文字和附件原子保存为一个 user 消息，由请求投影转换为可移植结构化资料文本，标明是资料而非指令，并计入上下文预算。发送后不提供移除附件的操作，后续页面变化不改写它；模型按书籍引用和精确范围调用工具。引用的正文身份失效时明确返回失效，不把旧坐标套到新正文。

显式添加附件每次产生独立出现项，按用户添加顺序保留；同一对象可添加两次，移除只作用于所选出现项。入口初始化的草稿附件仍只注入一次。

再次打开保留中的草稿不重复添加、不覆盖手动移除结果；新的显式页面唤起才生成新的页面附件。关闭弹窗保留本次阅读选择的对话、未发送文字及附件；退出本书后再进入，首次打开助手创建新对话，不自动选择正在运行或历史关联对话。历史对话可显式从标题菜单或对话 Tab 选择，月亮状态只反映本次选择。所有未发送输入及附件只在应用内存中保留，退出应用后清除；新对话首次发送前不创建历史记录；首次发送时保存对话及消息，之后失败或停止也保留历史。会话关联信息仍可用于导航检索，但不得在系统提示中偷偷重复附带已被用户移除的数据。

实现边界：已接入阅读页位置/选文附件、`+` 书籍/书签/批注选择、预览/移除、草稿保存、消息原子保存及请求投影。Agent 不发送固定页面提示；排队输入支持阅读附件，正式页面已接入工具活动、准备确认、steering/follow-up 与来源预览，旧文本服务已删除。小说详情、统计和书架目录／多选入口已接入同一快捷任务能力。生成图片的保存、历史展示与参考图引用已接入；用户主动添加外部图片附件尚未实现。

## 工具范围

| 类别 | 目标能力 |
| --- | --- |
| 找书 | 按书名、作者、标签、简介和阅读状态查找；列出目录与书籍 |
| 正文 | 读取目录、章节或指定范围；单书或指定书籍集合全文搜索 |
| 小说资料 | 读取、修改标题、作者、简介、标签、阅读状态 |
| 封面 | 网络检索候选、预览；按内容与用户要求生成图片；应用选定封面 |
| 笔记 | 查询书签与批注、生成笔记建议，按用户要求保存 |
| 阅读记录 | 查询期间时长、书目、阅读时段、章节估算覆盖与具体记录 |
| 文件整理 | 查询现有结构，输出结构化目标目录树与文件归属方案；模型不调用真实文件修改、移动或删除工具，应用负责校验、对比与确认执行，按风险选择保护措施 |
| 网络 | 搜索书籍信息、作者资料、推荐依据，读取相关网页 |
| 环境 | 当地日期时间、时区、界面语言与区域设置 |

`rg/read/ls` 延续已有方向，表示正文查找、读取和列举的业务能力，不是任意 shell 或文件系统权限。工具通过业务服务返回最终有效数据、稳定正文坐标，不直接暴露数据库、授权书签或私密路径。具体名称、参数、返回结构与限制见 [工具契约](../ai/tools.md)。

会话开始提供日期、时区、界面语言等基础信息，需要精确当前时间时再调用工具；不要求每轮先查环境。回答语言以用户要求为准。

统计数字、排序和覆盖率由业务工具计算，模型解释结果；不能把读得久直接断言为喜欢，也不能把估算覆盖说成确实读完。书内事实提供可跳回的章节/原文出处，临时查看不覆盖续读位置；找不到依据时说明。

## 小说详情与封面

- 文件名、现有资料和正文本身可能写明作者、简介和标签（用户提出）；模型可据此及配置的联网搜索补全，也可按用户要求提炼或撰写简介、标签。作者只采用明确署名，不从人物或文风推断；同名作品/不同版本在回答中说明。包含结局的梗概不能默认为无剧透简介。不新增出版、版本等字段。
- 网络封面只提供有出处的候选，用户选择，不把任意同名图片标为正式封面；所选服务支持生图时按正文概要和用户要求生成。未设置对应服务时不承诺可用。
- 页面、状态与应用流程见下文[快捷任务与业务结果](#快捷任务与业务结果)。

## 操作边界与阅读体验

- 用户发起问题后，在已授权书架内按需读取，不每读一章都询问。网络调用前通过配置和界面说明接收内容的服务及费用方式；不默认后台扫描或批量发送全书。
- 用户明确要求的单项修改可以直接完成；资料生成和封面替换按上述预览应用流程。文件整理统一遵循下述结构化方案流程，不向模型开放直接文件变更工具。问推荐、分析不隐含文件修改授权。
- 小说和网页内容、工具返回的文本不是用户指令，不能借其扩大访问范围或执行修改。AI 不直接改写小说正文。
- 支持停止请求；限制单次读取量与工具循环，避免无界调用。失败、重试和回答显示不阻断原阅读流程。
- 未下载、未解析和不可访问的内容必须准确告知可检索范围，不能假装完整检索。需要下载或准备正文时先提示用户，确认后再开始，不静默批量下载。
- 用户使用自带 API key 或供应商支持的订阅登录，应用不提供 AI 账号。订阅登录属于本次必须完成的范围，不得自行省略或延后；具体供应商、授权适用条件、模型和费用仍需验证；密钥不提交仓库、日志或普通同步记录。

## 已确认的技术分工

- AI 请求、流式对话执行、工具调度放在 Swift，选用 [teunlao/swift-ai-sdk](https://github.com/teunlao/swift-ai-sdk)。Rust 继续承担正文解析、搜索与计算；Swift 工具调用现有业务服务，不让模型直接访问数据库。
- SDK 负责供应商协议、结构化输出及工具调用数据；月读使用 SwiftUI 自行渲染消息、书籍卡片、正文引用、统计图表、资料修改预览、封面候选与文件操作清单。普通回答显示文字，不把所有回答强制转换成卡片，也不让模型生成可执行界面代码。
- 结构化输出使用 Codable / JSON Schema；真实书目、位置、统计数字来自业务工具，模型生成建议和解释。通过稳定对象身份连接卡片与应用操作。
- 供应商优先使用对应原生适配；兼容服务复用 OpenAICompatibleProvider。智谱 BigModel（国内）和 Z.ai（国际）使用不同配置预设，共用协议适配。
- 聊天、工具调用、图片输入和生图按模型能力区分。生图走独立能力，生成图片经预览后应用。
- 认证与计费分开：API Key 不等于按量付费，专用套餐 key 按服务商权益与使用范围处理。Copilot 完全移除；Kimi、Meta 与 xAI 不提供订阅／设备码登录，保留 API Key，Kimi 会员通过官方控制台取得 key。ChatGPT 账户使用官方 SIWC（公共 Responses、账户目录、SFSafariViewController + loopback），不提供订阅生图，不迁移旧 Codex 连接；OpenRouter 保留 PKCE。Coding Plan 不因协议兼容就作为通用小说对话额度。
- 产品工程已锁定并引入两库，阶段 1 文本对话已接入。独立验证已覆盖两库联合构建、模拟器 Markdown、可取消 transport，以及本账户 Codex 订阅的真实工具循环、生图和参考图编辑。真机完整登录、长历史、跨供应商回放等仍待验证，详见 [接入证据](../engineering/ai-feasibility.md)。

## 数据保存（已确认）

沿用 SwiftData 保存对话数据、Keychain 保存凭证；不新增 Rust 对话数据库。首版采用线性对话，不增加消息分支、版本恢复中心或持久化任务引擎。

| 数据 | 保存内容与位置 |
| --- | --- |
| 对话 | SwiftData：稳定 ID、标题、创建/更新时间、关联书籍或范围、所选服务配置与模型 |
| 消息 | SwiftData：对话 ID、稳定顺序、角色、时间、生成状态；文本、引用、工具调用和结果等有类型的内容部分 |
| 结构化结果 | 保存展示所需快照和稳定书籍/正文引用，历史可重现；点击时通过业务服务检查当前对象状态。持久化应用自己的 Codable 数据，不直接归档 SDK 运行时对象 |
| 续聊协议信息 | 保存下一轮确有需要的工具调用 ID、参数、结果及供应商要求的签名/不透明字段，关联原供应商和模型；发送时由适配层转换，不把不兼容字段发给另一家 |
| 图片附件 | 独立附件记录与受管理文件或 SwiftData 外部存储；消息引用附件 ID，不在每条消息 JSON 中重复内嵌图片。对话保留的候选图属于历史附件；缩略图可重建 |
| 已应用封面/资料 | 通过现有用户数据服务保存；独立于原对话，删除对话不撤销应用结果 |
| 服务配置 | 本机保存名称、地址、模型选项和凭证引用；API key、OAuth access/refresh token 进入本机 Keychain，不随普通用户数据同步 |
| 临时状态 | 网络连接、运行中的 Task、增量事件及预览下载临时文件不作为历史逐事件存储 |

流式回答节流保存已收到的内容，结束/停止时保存最终状态；重启后未完成回复显示为中断，不自动续费重发或重复执行修改工具。已发送内容作为消息保存；未发送输入仅在本次应用运行的内存中保留，关闭弹窗后重新进入可继续输入，不提前加入模型历史。

首版对话仅保存在本机，不随 iCloud 同步。候选图片随对话保留。删除对话同时清理仅属于该对话的附件；不会删除已应用封面、已保存批注或已执行文件操作。删书后保留对话与当时的引用摘录，原文入口显示不可用；相同正文再次可用时可重新定位。

正文工具读取结果应设置体积上限，避免对话无意保存多份全书；上下文裁剪独立于历史展示，不因发送窗口有限删除用户历史。

## 已确认的任务交互与执行归属

- 生成中追加消息采用 Pi 的 steering（在处理边界调整当前任务）与 follow-up（当前工作完成后发送）两种语义；steering 不等同立即中断请求，也不撤销已完成操作。默认使用 steering；发送按钮菜单提供“完成后发送”。不同对话允许同时运行，同一对话顺序处理。
- 快捷任务在点“开始”后才发出请求，结果或预览留在任务页，不进入对话历史；追问和修改要求在任务内用“补充要求”发送。只有显式“转入对话”才把同一任务的历史、过程、结果与附件保存为对话，不重新请求；附件随后遵循对话附件保存规则。
- 页面附件在唤起时取快照；页面滚动或对象后来变化不改写草稿快照和已发消息。附件随用户消息追加，系统指令不随页面改变；其他内容由工具按需获取。缓存命中取决于供应商，不优先于用户对输入的控制。
- 应用级会话服务按对话/任务 ID 唯一持有运行状态及请求，独立于具体页面；阅读弹窗与对话 Tab 观察同一份状态，不分别保存可写消息副本。SwiftData 为持久化记录，流式内容由该服务统一更新与节流落盘，界面不另做双向同步。
- 不可见时停止 Markdown 订阅、解析和动画等展示工作，网络任务及消息保存继续；再次可见时从最新快照恢复，不重复请求。
- 关闭弹窗不停止生成，再次打开连接同一任务。显式停止才取消实际请求，包括首字前等待和网络停滞，不能只改变界面状态。此规则不承诺 iOS 后台、系统挂起或进程终止后仍能持续运行；中断保存和重启行为沿用前述规则，不自动重发。
- 资料、笔记书签、封面与书架整理的结果均为可编辑预览，用户确认后由应用通过现有业务服务保存所选内容，见下节。

## 快捷任务与业务结果

### 通用任务页

所有快捷任务使用同一个 sheet（medium/large），分两个阶段，不另设设置页、任务中心或任务列表。

```
开始前                                   开始后（同一 sheet）
完善资料                        [×]      完善资料                [转入对话] [×]
[封面] 星灯渡口 · 原创作者甲               [封面] 星灯渡口 · 原创作者甲      ✦ 模型
✦ GPT-6.1 Sol 中 ›                       ▸ 读取文件名与正文 3 段 · 联网 1 次
[补充要求（可选）            ]           [准备正文？ 暂不准备 | 准备正文]
                                         正在完善 / 已停止 / 错误短句 / 简短回答
                    [ 开始 ]             〈领域结果〉
                                         [补充要求…                ] [↑]/[■]
                                                          [领域应用按钮]
```

- 首条用户消息以入口动作的本地化名称表达具体目的（完善资料／查找封面／生成封面／整理／分析阅读），下一行附可选补充要求，再附原有附件；界面显示与模型收到的是同一条请求，只发送一次。任务和普通对话使用同一系统指令，业务约束由对应工具说明提供。
- 开始前：对象标识、紧凑模型入口（以默认对话模型为初值，只作用于本任务）、可选“补充要求”和“开始”。“开始”是第一次发出请求和产生费用的边界，之后每次发送补充要求都会再次请求；开始前 × 直接放弃，不留下任务。任务内容由入口动作本身表达，不用字段勾选或来源模式开关；用户通过补充要求缩小或改变范围。
- 点击“开始”同步进入启动中状态，在异步创建会话前阻止重复点击；成功进入时间线，失败显示现有错误并恢复“开始”。
- 开始后：同一 sheet 改为同一聊天时间线、该轮已提交结果卡片与输入框，不再回到开始前状态。过程组、正文准备确认卡、来源预览、已停止/中断与错误短句直接复用对话的轮次视图，因此不另设状态行，只在运行中显示一行“正在完善/正在整理…”。紧凑模型入口在开始后位于输入框内（与对话相同），修改只作用于下一次请求。不放重试、重新开始或换模型按钮；转入失败的短句显示在结果下方。
- 输入框与对话语义一致：运行中默认 steering，菜单可选“完成后发送”；停止、失败或完成后发送普通下一次请求，保留已有过程和结果。失败后用户发“继续”。■ 显式停止；× 只关闭页面，不停止任务。
- 每个对象和任务类型关联同一持久未列出会话，从原入口（菜单项或状态行）直接回到它当前的阶段。任务不进入对话列表；关闭页面后继续运行，应用重新启动后仍可从同一入口重开。已应用的业务数据照常保留。
- “转入对话”只改变同一持久会话的列表分类并清除原入口关联，不重新请求、不交接图片；运行继续，固定 sessionID 的 sheet 始终使用同一聊天时间线。下一次从原入口打开进入开始前表单，对话仍可从对话列表打开。保存期间原任务保持可达，转入和移除不可用；失败保留任务和错误短句，可再次转入。关闭页面不取消保存，也不在结束时另弹提示。
- 未转入的资料或封面任务可从小说详情 `…` 菜单“移除资料任务／移除封面任务”显式移除。确认框只说明实际影响（进行中的请求会停止、任务及其结果会删除、已应用的修改会保留）；移除会停止该任务的请求，事务删除该会话、工作与会话资产，并解除原入口链接，之后入口重新进入开始前状态。已写入的资料和封面不回退。转入对话后的任务不提供移除，对话只在对话列表中删除。转入进行中不可移除，移除进行中不可转入。
- 每条 committed 工具结果保留不可变建议；每次打开复核，从该结果和当前业务数据重新建立编辑与默认选择，关闭后丢弃。不持久保留上次未应用的编辑、选择或应用状态，不重放模型。
- 结果卡片在对话历史中是当时结果的快照；“查看并应用”按当前真实数据重新核对后再写入。
- 无障碍：任务 sheet 标题为任务名；状态行作为状态值朗读；字段、候选和条目的选择用原生开关或勾选，并朗读当前值与建议值；所有操作保持 44pt 触区，大字号时左右结构改为上下排列。

### 完善资料

模型可读取文件名、现有资料与正文，配置了联网搜索时也可搜索；作者只采用明确署名，简介与标签可提炼或撰写。阅读状态由用户管理，默认完善资料任务不建议修改，也不从阅读进度或覆盖率推断；普通对话中用户明确要求修改时，可产生该字段的待确认建议。

复核采用[结果卡片与资料复核](#结果卡片与资料复核)的最终效果视图：变化文本默认采用建议，用户可切回原值或编辑；新增标签默认采用，replace 移除默认保留。省略字段不写，与当前相同的字段不计更改。

来源只解析同会话完整成功工具历史：原文摘录打开只读预览，不改续读/统计；网页打开来源页，文件名可作为依据但不是可打开引用，不展示置信度仪表盘。保存前 fresh-current 复核，仅写本次所选字段；变化需用户重新确认，不承诺跨设备原子性。每条结果一本书，多书任务产生多条独立结果，各自打开、保存和报告；原始建议可重复使用，不保存应用回执。

### 笔记与书签建议

在阅读弹窗或对话中，模型按用户要求给出的批注与书签建议显示为结果卡片：

```
笔记建议 · 3 条
[✓] 第十二章 · “三十年河东……”            ›   摘录点开为只读原文预览
    [萧炎第一次表明立场，与退婚呼应______]
[✓] 第十五章 · 书签                       已有书签
                                   [保存所选 (2)]
```

- 批注：评论可编辑；保存走现有批注准备与保存流程。范围与已有批注交叉时，该条进入现有批注编辑器，已有评论与建议文字分段预填，由用户按既有合并、冲突规则确认，不自动合并。成功保存才将原建议标为已保存；取消编辑或保存失败保持待处理，批量建议各自对应自己的编辑结果。对话中的资料、封面与整理建议同样以卡片呈现：资料卡片“查看并应用”打开同一审阅页，封面与整理直接在卡片内审阅。
- 书签：确认是“确保存在”，已有书签显示“已有书签”且不切换，已经是已解决状态，不计入待处理／保存所选；使用业务层原子的确保存在操作，不复用切换按钮。
- 笔记 review 使用一个结果状态：待处理、已有书签、已保存、暂不可用（具体原因）。待处理数包含所有 pending 项，与勾选无关；保存所选仅计 pending 且勾选项。已保存／已有书签不能重复保存。瞬时保存错误单独显示短句，保留勾选、编辑内容和同一个保存按钮；再次编辑或显式保存清除旧错误，不自动重试。
- 原文当前不可用的条目显示“暂不可用”及真实原因，不能保存，不一概宣称原文已变化。历史恢复按当前可用正文和书签重新投影，不自动下载，不恢复虚构的已保存状态。
- review 持有保存状态和待编辑队列；一次批量保存不能覆盖未关闭的编辑器队列。只有发起卡片可呈现／关闭自己的队列，卡片离开或下拉取消不标为保存，迟到的准备结果不会留下阻塞队列。实际编辑器成功提交的回调仍准确解决原建议，即使呈现宿主已离开；回调幂等。

```
                    [ 开始 ]             600×800 · 某站     生成
```

- “查找/生成”是开始前唯一的模式选择，因为它决定使用的服务与费用。未设置联网搜索或图片生成的一侧不可选，并显示“未设置联网搜索/未设置图片生成”，可进入对应用途设置。
- 查找：采用搜索来源图片直链，或由应用本地从授权来源页面提取一层显式图片；不猜地址、不沿链接递归、不把网页正文交给模型。获取契约见[封面页面提取](../ai/cover-fetch.md)。搜索的简短回答与网页链接属于工具过程，在“查看过程”的工具详情中查看；封面结果区只放图片候选与应用，没有图片候选时显示“没有图片候选”。
- 真实搜索与封面使用结果见[验证记录](../engineering/verification.md)。不新增通用 URL 后缀、MIME 或字节上限；封面候选有独立尺寸筛选。
- 生成：图片使用默认生图服务；可在补充要求中描述风格。
- 每条已提交结果的候选网格按图片资产身份保留，重复建议的原始过程历史不改写，不比较图片 bytes。候选没有“当前封面”或“已应用”标记；来源为网页域名、生成或中性的封面参考／图片，不以来源证明当前业务封面。
- 候选两列网格（大字号时单列），显示缩略图、尺寸和来源域名或“生成”。点开为大图预览，提供来源链接、“设为封面”和“以此修改”。“以此修改”把该候选作为参考图放入输入框；结果区另有“以当前封面修改”。编辑交给已配置的图片工具执行，失败由实际执行结果说明；不新增入口或发送前能力限制，不自动切换模型。参考图附件可预览真实图片及逐项移除，界面不显示内部引用 ID。它表示交给图片工具的参考图，不表示对话模型已经看过像素。
- 每个候选始终提供“设为封面”，通过现有封面资源与资料保存流程写入，保存期间禁用点击。成功即时显示“封面已更新”，sheet 保持打开，仍可再次设为封面。当前业务封面从资料读取，不重复放一张大图；原有当前封面变化检查保持，不新增回执、当前候选或已应用状态。

### 书架整理

所选项目或目录作为用户输入的上下文，不是隐藏的文件白名单；所有会话使用同一提案工具，模型可提出不同范围的方案供用户审核。scopeRef 声明本次方案的范围。只建目录、重命名、移动，不删除、不覆盖，未出现在用户确认方案中的文件保持原样。

```
整理 · 我的书架/玄幻                      [转入对话] [×]
[ 变更 | 全部 ]
▾ 原创作者甲/                        新建   [✓]
    星灯渡口.txt        原位置：玄幻/       [✓]
    远山邮局.txt        原名：远山.txt      [✓]
▾ 原创作者乙/                        新建   [✓]
    云海拾光.txt        ⚠ 同名文件已存在   [改名…]
                         [执行 5 项]
```

- 默认只显示变更，按目标目录分组；“全部”显示应用所含变更后的完整目标树（只读，新建、移动、改名以强调色标注原位置或原名），编辑只在“变更”中进行。目录与文件的目标名称可编辑；每项和每个目录可取消。冲突（同名、非法名称、超出范围、所在新文件夹未包含等）就地显示，存在冲突的项不能执行。大字号时改名与包含控件移到名称下方。
- 方案关联预览时记录的真实来源与目标身份。“执行 N 项”在打开确认框时固定该方案中可执行项的 ID 和数量（新建 a · 移动 b · 重命名 c），执行只处理该集合；逐项重新核对，跳过已变化、已取消包含或新冲突的项。自身操作释放的名称会更新剩余冲突，但不会在本次确认中自动加入新解锁的项；例如 A→C 完成后，B→A 必须另点“执行剩余”并确认。
- 同卷使用文件系统移动/重命名；跨卷或跨提供方需要先复制、校验、再移除来源的业务操作，失败保留来源。逐项显示进度，不保证文件系统与数据库的整体原子性。
- 中途失败或停止后逐项显示“已完成/未完成（原因）”，“已移动但书架记录未更新”“已复制、原文件仍在”“未能确认”单独标出且不计入可继续执行的项，不回滚；“执行剩余 N 项”只对未移动的项在重新核对后继续。该列表只在本次启动中保留；应用被终止后，已执行的文件变化真实存在，书架显示实际现状，没有可恢复的进度列表。

## 阅读月亮入口

2026-10-16 起改为「月光」：助手就是桌面图标里那弯月亮，不画五官、不拿道具，状态用月光的亮度和月相表达（取代带表情与道具的「月牙」角色，已实现）。源码：`Shared/Components/MoonCharacter.swift`（形象与状态绘制）、`AI/UI/AIReadingMoon.swift`（阅读页提示与动画）。静态状态稿见 `build/IconExplore/assistant-states.png`（本机预览，不提交）。

### 形象

- 一枚 40pt 的深蓝圆盘里放一弯暖金月亮，是桌面图标的缩影：圆盘 `#1F2C5C`，月亮 `#F7C75F`，与图标同一套品牌色，不随阅读主题变化。在浅色和深色阅读纸上都清楚，56pt 画布、整个画布可点。
- 弯月几何与图标一致：外圆减内圆，内圆半径 0.84r，偏移方向 (0.8, −0.6)。月相由内圆偏移量 k 控制：细月 k = 0.5，较满 k = 1.35，切换时插值，看起来像月亮渐盈。
- 圆盘外沿保留 paper 色间隙与轻阴影，正文字形不贴住它。
- 不再区分查找、阅读、创作、建议、思考等工具姿态；当前在做什么由对话和 VoiceOver 值说明，月亮只表达“在工作 / 等你 / 有结果 / 出错”。

| 状态 | 来源 | 静止形态 | 动作（允许动效时） |
| --- | --- | --- | --- |
| 空闲 | 无任务，或任务仅在回复/整理上下文 | 细月 | 无 |
| 正在回答 | 任何工作中的运行状态（含各类工具调用、推理） | 细月，月亮提亮，圆盘外一圈淡金光晕 | 光晕约 3 秒一次缓慢呼吸（不透明度 0.10–0.22） |
| 等你确认 | `waitingConfirmation` | 细月 + 右上 10pt 系统强调色圆点 | 无 |
| 完成 | `completed` | 较满月相 | 月相 0.4 秒渐盈，光晕亮起一次后散去 |
| 有结果待看 | 完成且本轮有成功的 `propose_*` 结果 | 较满月相 + 右上金色圆点 | 同完成 |
| 未完成 | `failed`、`limitReached`、`interrupted` | 圆盘与月亮降低亮度 + 右上系统红色感叹号徽标 | 无 |

- 状态切换 0.2 秒交叉淡变；少于 300ms 的工作状态不显示，已显示的工作状态至少保持 1.2 秒。等你确认与结果状态立即切换。用户主动停止不显示任何结果。
- 空态（空文件夹、对话列表、空对话）与设置里的阅读预览使用同一形象的空闲状态（`MoonView`），不再有表情。

### 何时出现

- 阅读时月亮**默认隐藏**。打开阅读操作层时出现，显示当前状态：任务进行中显示实时姿态（含等你确认），任务结束后显示尚未查看的结果（完成·待查看、未完成），否则为静止姿态。
- 只在本次开书所选对话的状态**变化**时短暂出现（以本次阅读观察到的变化为准，重新开书、刷新或旧结果都不会重播）：

| 事件 | 显示 | 时长（可调） |
| --- | --- | --- |
| 关闭对话时任务仍在进行 | 当前工作姿态 | 2.5 秒 |
| 进入等你确认 | 等你确认 | 6 秒，然后隐藏；打开操作层时再次显示 |
| 完成 | 完成 | 2 秒，之后不保留 |
| 完成·待查看 | 完成·待查看 | 4 秒；之后在操作层中保留到打开对话 |
| 未完成 | 未完成 | 5 秒；之后在操作层中保留到打开对话 |

- 对话打开期间发生的变化已在对话里可见，不再提示。打开对话即视为已看到结果，只清除展示状态，不改写任务结果。新的运行开始后旧结果不再显示。
- 提示等到页面平静再出现：后台、导航定位、跨页选取、底部面板/搜索/任务页打开期间不显示，条件恢复后再显示；正在显示时被这些情况打断则结束本次提示。范围只限本次开书选择的对话，不回退到其他运行中或历史对话。
- 出现和离开都是 0.3 秒淡入淡出，不上浮、不弹跳。减弱动态（系统或应用）时淡变缩短为 0.15 秒，光晕不呼吸、月相直接切换，各状态显示静止形态。呼吸动画只在可见、前台且允许动效时运行，不可见即停止。
- VoiceOver 名称“月读助手”，提示“打开对话”，值为当前活动标题或结果（“已完成”“已完成，有建议待查看”“未完成”）。等你确认和结果出现时以低优先级播报一次。
- 位置可拖动，默认右下；标题区和药丸区域为禁入区。按下时轻微缩小，减弱动态时改为降低不透明度。

## 长对话与上下文管理

Pi 源码对照、具体 SDK 接口及已完成验证见 [AI 接入调研](../engineering/ai-feasibility.md)。

界面历史与模型输入是两个独立问题：

- 消息列表使用 UITableView 按块复用，文本块为原生 Markdown；历史按页读取，保持稳定消息 ID 和加载旧消息时的可视位置。懒创建视图不等于自动分页，也不保证任意长列表的内存上限。流式回复只更新相关消息，用户翻看历史时不强行滚到底部。
- 自动压缩不删除用户可见历史。保存完整历史及单独的摘要检查点，下一轮请求使用固定指令、摘要、近期完整轮次和必要工具信息。
- 按模型可用上下文预算触发，预留回复及工具结果空间；有服务返回用量则使用该信息，否则保守估计，不能把字符数当精确 token 数。阈值按[Agent 预算](../ai/agent.md#上下文预算与压缩)计算，不逐轮重写摘要。
- 优先限制正文工具返回量与分页；仍接近预算时调用模型总结较早的完整轮次，保留用户要求、关键事实、原文来源 ID、已应用操作与未完成任务。摘要成功后才切换输入；不拆散尚未完成的工具调用与结果。
- 通过选定 SDK 的 prepareStep 钩子组织每步 messages；摘要生成及检查点由应用会话层实现，不把其他同名 Swift SDK 或上游 TypeScript 功能视为本库自带能力。
- 压缩期间显示“整理上下文”，允许停止；失败时保留历史并显示简短错误，用户通过普通输入继续，不反复自动消耗额度。摘要不能当作新的操作授权。稳定前缀只在必要压缩时调整，缓存优化不能优先于输入正确性。

模型设置呈现随页面实现，联网使用用户配置的搜索服务及其原生搜索。以上不增加额外后台执行、消息分支或恢复中心。

## 模型配置与快捷结果（已确认方向）

- 统一入口已确认：一个模型按钮同时承载供应商/连接、模型、思考档位选择，不要求先进入供应商页面。供应商图标随应用打包，按品牌映射区域/套餐；使用 Gupi 复用资源和 LobeHub 补充资源，保留来源及许可证，未知供应商使用通用图标。
- 选择器交互以本文下方“模型入口与选择器”为准：输入框内紧凑按钮打开模型/思考小面板，再进入按连接分组的名称选择列表。连接名称在弹层内展示，避免同名模型选错账户；没有可用模型时提供连接设置入口。
- 对话入口与设置页面的默认模型共用同一选择器组件，按调用场景保存到当前对话或默认配置；不显示“仅用于当前对话，不改变默认模型”这句说明。设置入口不能只复用外观而保留另一套选择逻辑。
- 运行状态提示“下一次请求生效”；不取消正在生成的回复。切换模型时校验档位，优先使用该模型有效默认值，不把不支持的旧档位带过去；不支持可调思考时隐藏档位控件。模型较多时原生列表滚动，常见操作留在同一弹层。草图中的其他供应商仅为设计样例，不代表当前产品已支持。

- 可配置多个供应商和模型，设置默认对话模型，并独立配置联网搜索、图片生成服务。同一模型支持多种用途时可同时作为多个默认项，不要求用户重复配置；图片输入、图片生成、图片编辑分别判断能力。
- 搜索、生图配置独立于当前对话模型：先选支持此用途的账户连接，再选该通道的模型。未加载目录的连接仍可进入管理页完成登录和加载；不自动选择账户或模型。ChatGPT 账户只提供允许的搜索，不进入图片生成用途；OpenAI API 生图的执行模型不冒充实际绘图模型。不自动切换账户或付费路径；未设置时可在设置中选择。接口与本轮范围见[原生工具契约](../ai/native-tools.md)。
- 运行前及对话中允许修改模型，并考虑思考强度。参考 Pi，当前对话选择与全局默认分离，临时切换不改全局默认；仅展示模型支持的思考档位。请求生效边界：已发出的请求不替换，下一次请求应用新选择，并明确显示。
- 快捷任务从原入口重新打开当前结果，不进入对话历史；未转入对话的任务在应用重新启动后仍可从同一入口重开，已应用成果不受影响。页面与转入规则见[快捷任务与业务结果](#快捷任务与业务结果)。

## 连接与模型设置

本节描述完整产品设计，不以阶段性接入状态定义页面。实现进度与未完成工作记在计划及验证记录中；页面不展示开发待办或“月读尚未接入”清单。

设置中的“AI 助手”页先列“默认使用”（对话、联网搜索、图片生成），再列“连接”，顺序固定。连接页以账户和连接管理为主：未登录、获取登录码、等待授权、已连接和错误状态分别呈现。验证码支持复制，授权使用应用内浏览器。模型加载失败保留已有目录与登录状态，提供重试；明确认证失效才要求重新登录。返回不取消授权，取消操作只影响当前连接。通用使用说明集中在 AI 总页帮助入口。

添加页以“账户登录 / API Key”原生分段控件区分认证方式，套餐 Key 仍属于 API Key。选择供应商后关闭添加弹层，直接进入新连接详情；返回回到发起添加的页面。“AI 助手”页、工具服务页和模型选择器的空状态共用同一添加流程，不再嵌套打开另一份 AI 设置页。同一供应商可建立多个独立连接，同名新增连接自动编号，名称旁的铅笔可改名。

详情顶部为供应商图标、连接名称和认证方式；其下账户/凭证卡片包含状态、登录或输入 Key、重新登录/更换 Key，以及危险色“移除连接”。移除需确认，清除连接配置和本机凭证，停止该连接正在运行的请求，保留对话；不影响其他连接。被移除连接若是默认连接，则清空默认选择，不自动使用其他账户。下方直接展示模型分组卡片，标题旁显示数量和刷新按钮，行内只显示模型名、默认模型标记和详情箭头；点击进入模型详情，不再增加独立目录页。刷新时保留已有列表，失败在模型卡片内提供错误与重试。更换 API Key 时，凭证写入失败保留输入和编辑状态并在凭证卡片显示错误，旧凭证仍已配置不代表新 Key 保存成功；凭证写入成功即可关闭输入，后续模型刷新失败仍在模型卡片反馈。账户操作均在模型列表前，不放在长列表底部。所有页面使用现有主题角色及原生导航。

### 模型入口与选择器

对话输入框内默认只显示供应商图标、模型名与思考档位的紧凑按钮。点击打开小面板，呈现模型入口和离散思考滑杆；点击面板中的模型入口再打开分组选择 sheet。关闭面板后滑杆不占对话空间。设置默认模型复用该交互，置于主题分组卡片。

选择 sheet 使用原生分组列表/选择能力，按供应商与账户分组，行内只有模型名称和选中状态，不附容量、能力或详情按钮。取消或下拉关闭不写入，完成后应用。思考档位按真实模型数据映射，不写死数量；使用原生 SwiftUI Slider 按整数步长选择，iOS 26 起显示系统刻度，旧系统保留原生滑块。用户切换到不同档位时触发系统 selection 触感反馈，同档移动与配置刷新不重复触发；无思考能力不提供调节，单档仅显示。对话选择与默认配置独立；已发送请求保留原配置，下一次请求使用新选择。

### 模型启用管理与选择器搜索

2026-10-05 已实现。连接页模型卡片在编辑模式或模型超过 12 个时显示搜索。

管理与选择分开：连接详情管理模型是否参与新的选择，选择器继续保留连接分组、模型名和选中状态。

| 位置 | 交互 |
| --- | --- |
| 连接详情模型卡片 | 标题显示“已启用 5 / 390”，保留刷新并增加“编辑”。普通模式保留全部模型及详情入口，停用项以次级样式和“未启用”标识；编辑模式显示搜索与逐行原生开关，立即保存，“完成”仅退出编辑 |
| 批量管理 | 无搜索时为“启用全部／停用全部”；搜索后为“启用 N 个结果／停用 N 个结果”，只作用于当前匹配结果。单项与批量遵循同一规则，不为默认模型增加例外 |
| 对话与默认模型选择器 | 原生搜索始终可用，匹配模型名称、ID 和连接名，不区分大小写；结果仍按连接分组。搜索激活时升到 large sheet，收起搜索后不自动缩回。搜索激活时系统用搜索栏替换“取消/完成”，因此在搜索结果中点选模型会结束搜索并保留草稿，再由“完成”应用；紧凑入口、小面板与思考滑块保持 |
| 搜索与生图用途 | 保留先选服务；模型行进入该连接内可搜索的选择列表，复用模型行和搜索规则并叠加真实用途能力筛选。点选只更新用途页草稿，用途页“完成”才保存 |
| 模型详情 | 停用项仍可查看；显式点击“使用此模型”同时重新启用 |

启用偏好按连接 ID＋模型 ID 保存，与目录记录、账户权限和能力分开。内部使用每个连接的 `disabledModelIDs`，随本机连接配置保存，不新增云同步。刷新不清除停用记录，模型消失后再出现仍保留偏好；手工添加模型显式启用该 ID。

停用表示不提供给新的选择，不取消运行请求、不改变历史、思考配置或既有默认项，也不自动换账户／模型。各选择目标当前已经使用的停用模型仍保留并标注“未启用”，直到用户选择其他模型；搜索仍正常过滤当前项，筛掉选中行不会丢失草稿或使“完成”失效。其余停用模型不因搜索而重新出现。管理说明只在编辑区保留一句：“停用后不再提供给新的选择，已有选择不受影响。”

默认对话、当前对话、搜索、生图共用启用偏好，不增加按用途分别开关。选择器行不加入开关、能力资料或重复帮助；同连接内名称确实重复时才补模型 ID，不给所有行增加副标题。搜索无匹配使用原生搜索空状态；有合资格模型但全部停用时提供“没有启用的模型”和管理入口，多个连接按连接列出。管理入口进入现有连接详情的模型编辑区，返回保留选择草稿。连接标题与开关行适配大字号及长名称，操作目标沿用 44pt。

首次加载目录时全部启用，刷新后新出现的 ID 同样启用，用户停用的 ID 持续保留；不猜热门型号、不按供应商规模挑选子集，也不提供“新模型自动启用”设置。连接尚未选定模型（modelID 为空）时，自动选定第一个已启用的文字模型。

### 模型详情与能力数据

详情采用稳定顺序：身份与连接、能力概览、思考调节、容量、使用按钮。不设“模型资料”展开区；模型 ID 与名称不同时放在名称下方并支持复制，来源和更新时间内部保存。必要限制体现在相关项目，有准确的官方模型链接才显示底部文字入口。能力分组使用三列两行、图标在名称上方：第一行为文字对话、图片输入、深度思考，第二行为图片生成、工具调用、结构化输出。按 models.dev 明确支持的字段启用，其余在固定位置置灰，不显示“未知”或阶段性未接入说明。具体字段映射、资料匹配、缓存与刷新见[模型目录方案](../engineering/ai-model-catalog.md)。

页面读取统一模型资料，不在 View 内按某一型号写死能力。供应商、接口及精确模型身份共同决定匹配，不能把 API 规格自动套到订阅连接。同一份解析后的能力与限制供选择、详情及请求使用；供应商运行时明确返回的账户目录/限制优先于匹配的通用资料，缺失字段可由经过核对的目录补充，不用猜测补值。能力支持与账户暂时失效等运行状态分别处理。

Pi 使用内置目录、本地 models-store.json 与运行时远端覆盖；部分入口触发刷新，远端目录通常有 4 小时缓存窗口。月读采用内置快照、应用级缓存及后台按需刷新，公开能力目录与账户目录分开，具体策略见[模型目录方案](../engineering/ai-model-catalog.md)。

详情配置为本次查看的草稿，返回不保存，使用模型后应用到进入时的目标。供应商图标来源见 `ios/Moonread/AI/PROVIDER-ICONS.md`。未完成项见 [AI 计划](../plans/ai.md)，验证结果见 [验证记录](../engineering/verification.md)。

模型目录字段核实（2026-10-03）：models.dev 最终模型 schema 要求 `attachment`、`reasoning`、`tool_call` 为布尔值，`modalities.input/output` 为支持类型列表；基础元数据/覆盖片段中的可选字段不能当成最终记录缺失。当天公开 api.json 的 8,385 条供应商模型记录中，这四项均存在。Pi 以 `reasoning === true`、输入列表包含 `image` 等条件确定能力，未提供肯定支持时不启用，没有给这些能力另建用户可见的未知状态。models.dev 没有独立统一的联网搜索/图片编辑字段，不能用 tool_call 或同时支持图片输入输出替代这两项判断；需核对相应服务适配器。ChatGPT 目录只以账户明确返回的字段为准，尚未取得真实目录时不推断字段必定存在；缺少上下文容量时只编辑该账户已返回型号的用户预算。

### 编辑与关闭按钮

编辑和选择页统一使用文字：左侧“取消”，右侧按操作使用“保存”“完成”或“应用目录”。取消丢弃未应用修改；纯浏览、对话和搜索的收起入口使用 ×，不伪装成取消保存。维持既有无障碍标识与行为。

### 资料与封面的应用反馈

资料与封面保存期间禁用应用按钮。真实业务保存成功后即时通知并刷新当前资料／封面；不持久记录应用成功、失败、回执、未确认锁或已解决候选集合。原始建议保留，编辑和选择只存在于本次复核，同一建议或候选以后仍可再次应用。当前值来自实际业务数据，历史建议不代表当前值。

结果卡片在成功工具消息进入当前会话投影时解码一次；仅保存已加载消息的类型化显示数据，流式期间不重复解码，显示在所属轮次内；旧页加载时带出对应卡片，不在启动时全量恢复结果或保存全局结果目录。复核和应用使用卡片携带的原始结果，编辑/选择仍只存在于本次复核。任务入口不显示历史总结果数量，移除说明任务及结果会删除、已应用修改会保留。

## 结果卡片与资料复核

整张结果卡是有按压高亮的单一按钮，摘要只列变化字段并标字段名，标签用 +/−；底行“查看并应用”。封面摘要最多4张缩略图，底行“选择封面”。反馈在卡内，辅助功能读出类型、数量及动作。附件头参与列表滚动，不叠压正文；复核底栏用 safeAreaInset，消息列表的输入区/胶囊按[消息呈现](../ai/rendering.md)处理。

资料复核直接呈现类似小说详情的最终效果：新增标签默认选中并标“新”，取消为灰色删除线；replace 的建议移除默认不选、保留原标签，虚线“建议移除”，显式选择后删除线。不变标签不可点。变化文本只在“已修改 ⇄”标记切换建议/原值，空值显示“保持空白”；编辑后成为新建议并标“已编辑”。有来源才显示 host 入口；阅读状态只在用户明确要求时出现。大字号 chips 换行，无障碍说明当前选择与点按后果。

底栏“应用 N 项更改”按实际写入计数：每个文本字段一项、标签整体一项、重命名一项；0项禁用。每条结果一本书，关闭丢弃本次编辑和选择，不存应用回执或锁定再次使用。

书名是实际文件名，没有显示别名。rename 的 fileRef 必须属于该 bookRef，name 为文件名主干并保留扩展名；仅文件名夹带作者/站点/格式/完结噪声或用户明确要求时建议，不翻译、不按正文猜书名。应用重新解析 fileRef 并校验原名/字节基线，replace=false；冲突、变化或权限失败明确报告，不覆盖/自动换名。metadata 与重命名分别执行报告，非原子；同 SHA 数据保留，只改选定副本，展示原名→新名。

小说详情的两个 AI 入口横排，大字号改竖排；标签/简介字号不超过作者、保留间距，展开简介靠左用强调色。封面候选固定3:4框、fit、底部对齐，修改当前封面为次级图标入口；没有重复的大当前封面、当前候选或已应用徽章。来源、参考图编辑与应用语义沿用上文。
