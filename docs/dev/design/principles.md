# 界面设计原则

设计、原型和实现界面时共同遵守。具体页面的决定写在各自文档；颜色与样式来源见[界面样式归属](ui-inventory.md)。

## 系统组件优先

- 先确认系统是否已有对应组件，使用系统容器、控件、导航、菜单、sheet、搜索与状态样式，让系统决定外观和不同尺寸下的表现。只有系统没有等价物时才自绘（如正文分页、双页、纸张纹理）。
- 图标用最简单的系统 SF Symbols，不自绘圆底、描边等装饰。完成、空、错误等状态用系统居中状态样式（如 `ContentUnavailableView`）。
- 共享控件在原处改进，不为单个页面复制一份。

## 菜单与操作确认

- 确认一件具体、不可撤销的事（删除、清空、移除、退出账户等）用系统居中 `.alert`；标题直接说明对象，说明只写实际后果，没有额外后果就不加说明。破坏性按钮用相应动词及 destructive 角色，并提供“取消”。
- 从一个按钮出发在几个动作里选择，用 `Menu`，不叠加多余确认。
- 只有确实需要确认且确认中有多个业务选项时才用 `confirmationDialog`，并挂在触发按钮上；取消不算一个业务选项，不把它挂在整个列表/页面上。
- 已有真实撤销或最近删除可直接恢复的操作不先确认；左滑删除不可恢复时用 `.alert`，可恢复则直接执行。不为此新增撤销机制。文件删除以实际 `trashItem` 成功为准；失败时必须先用居中 alert 明确告知将永久删除、无法恢复，获同意才永久删除，不按 iCloud 或本机位置假定可恢复。书架移除保留确认；筛选条件组删除及缓存清理仍确认，导出全部备份直接生成并走系统分享，沿用现有进度反馈。

## 可左滑的列表

- 可左滑的圆角分组列表统一用共享的 `ThemedGroupedList`（`Shared/Components/ThemedGroupedList.swift`，UICollectionViewListCell + `UIBackgroundConfiguration`）绘制主题行底，不用 `listRowBackground`，左滑时由系统保持圆角形状。
- 左滑删除、移除等破坏性操作使用系统红色。
- 不可左滑的列表和 `.plain` 列表维持现状。新界面中的可左滑列表按此实现。

## 原型与实现

- 界面原型（HTML 等）用于确定结构、层级、内容和交互，须按 iOS 系统组件的实际外观来画，不画系统组件给不了的样式。
- 实现时用系统组件；原型与系统组件外观不一致时以系统组件为准，并把差异说明给协调者，不为还原像素手写控件。

## 不用列表偷懒

- 主要操作是真正的按钮，进度用进度视图，错误和警告用横幅或空状态，说明放在脚注或说明文字中。
- 不把状态、按钮、错误塞进 List/Form 行；设置和操作按用户要完成的事分组，破坏性操作与普通操作分开。

## 不为单个页面改共享界面

- 导航栏、标签栏等属于整个导航栈或根界面。不为某个页面调用会影响其他页面的全局状态，不让同一组件出现两个状态归属方。
- 确需改动共享界面时，先说明影响范围，再小步验证。
