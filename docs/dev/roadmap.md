## 书架交互待实施

2026-10-14 已确认方案；默认网格、最近删除和拖动移动已实现（见[首页与书架](design/library.md)）。最近删除的真机结果与用户接受的缺口、拖动的本地回归与最终试用缺口见验证记录。

### 1. 删除改为移到“最近删除”（已实现）

当前设计见[首页与书架](design/library.md#文件操作)，实施及阶段 0 依据见[计划](plans/library-trash.md)。

- 每项直接调用 `FileManager.trashItem`，在 ReaderService actor 外执行，保持安全作用域到 IO 结束；不放入协调写入。系统成功后异步重扫，刷新失败不改成永久删除重试。
- 移到最近删除失败即按不支持处理，本批暂停，只问一次“永久删除这些项目 / 跳过”；之后只有再次移到最近删除失败的项沿用本批选择，不静默降级。路径校验与永久删除错误照常报告，批次结束清空选择。
- 删除前取消该路径及后代的开书准备，不承诺系统下载或全部 IO 停止。书架书签解析出的根包含 `.Trash` 路径段时显示“需要重新连接”；恢复后按 SHA 接回阅读数据。iCloud 短暂闪回跟随系统，不做过滤。
- 阶段 2 内置 iCloud 与 iCloud Drive 外部单文件可移到最近删除，并通过 Files“选择 → 恢复”恢复；长按无恢复菜单，用户接受。本机外部 trash 失败改为本批确认永久删除或跳过；本地内置根、未删文件夹与跨设备同步不补测、不新增通过结论，结果见验证记录。

### 2. 拖动移动（已实现）

现行规则见[首页与书架：操作入口](design/library.md#操作入口)。

- 列表和网格共用的 `UICollectionView` 使用原生拖放委托：抬起预览、悬停文件夹高亮、边缘自动滚动、悬停自动进入文件夹。首页书架行可作为放置目标并支持悬停进入，以便跨书架拖动。
- 放下按 ID 重新取条目后走与菜单“移动”相同的 `LibraryCommand.move` 流程；自己或后代、同父目录、出错书架、忙碌及多选模式下不可拖放。用户手动移动是否改为“复制、校验、删源”另行决定，本轮不改。
- 托管长按菜单保留；模拟器静止长按菜单可用，正式拖放回归通过，无需自建手势。
- 支持从“文件”等 App 拖入 TXT，仅限“我的书架”，复制到暂存后走现有导入。
- 不做手动排序：书架是真实文件夹，按名称或时间排序。
- 首页接收规则及根目录执行已有单元覆盖；公开 XCUITest 无法驱动“悬停返回后再移到首页”的连续手势，跨页与跨 App 拖入的手感留待最终试用，不将工具限制当成范围回退。
